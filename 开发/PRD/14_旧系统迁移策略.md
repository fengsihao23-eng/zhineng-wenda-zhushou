## 1. 迁移总体策略

### 1.1 三阶段迁移

```text
阶段一：只读共存
    旧系统继续运行
    新系统通过 Adapter 只读旧数据
    验证数据正确性

阶段二：双写验证
    新数据写入新 PostgreSQL
    同时同步到旧 MySQL（或反向）
    两边数据对比验证

阶段三：切换主系统
    新 PostgreSQL 成为 Source of Truth
    旧系统降级为备份/只读
    逐步下线旧功能
```

### 1.2 核心原则

> **旧系统是资产，不是垃圾代码**

- ✅ 保留旧系统业务能力
- ✅ 通过 Adapter 渐进迁移
- ✅ 数据先行，业务跟进
- ✅ 随时可回滚

### 2.1 目标

```text

    ↓
StudentDataAdapter (接口)
```

```python
    async def get_student(self, student_id: UUID) -> Student:
        """从旧表读取学生"""
        async with self.engine.connect() as conn:
            result = await conn.execute(
                text("""
                    SELECT 
                        id as external_student_id,
                        name,
                        student_no,
                        grade_id,
                        class_id
                    FROM old_students
                    WHERE id = :student_id
                """),
                {"student_id": str(student_id)}
            )
            row = result.fetchone()
            
            if not row:

                id=uuid4(),  # 新 UUID
```

### 3.3 数据一致性验证

```python
class DataConsistencyChecker:
    """数据一致性检查"""
    
    async def check_exam_scores(
        self,
        date_from: date,
        date_to: date
    ) -> ConsistencyReport:
        """对比新旧系统数据"""
        
        # 从新系统读取
        new_scores = await self.postgres_repo.list_exam_scores(
            date_from=date_from,
            date_to=date_to
        )
        
        # 从旧系统读取
        old_scores = await self.legacy_adapter.list_exam_scores(
            date_from=date_from,
            date_to=date_to
        )
        
        # 对比
        mismatches = []
        for new_score in new_scores:
            old_score = self._find_matching_old_score(
                new_score,
                old_scores
            )
            
            if not old_score:
                mismatches.append({
                    "type": "missing_in_old",
                    "new_id": new_score.id
                })
            elif not self._scores_match(new_score, old_score):
                mismatches.append({
                    "type": "data_mismatch",
                    "new_id": new_score.id,
                    "old_id": old_score.id,
                    "diff": self._compute_diff(new_score, old_score)
                })
        
        return ConsistencyReport(
            total_checked=len(new_scores),
            mismatches=mismatches,
            consistency_rate=(len(new_scores) - len(mismatches)) / len(new_scores)
        )
```

## 4. 阶段三：切换主系统（Week 7-8）

### 4.1 切换条件

**必须满足**：
- [ ] 双写运行 2 周无重大问题
- [ ] 数据一致性 > 99.9%
- [ ] 新系统稳定运行
- [ ] 所有核心业务功能验证通过
- [ ] 回滚方案准备好

### 4.2 切换步骤

```text
1. 停止新数据写入旧系统
2. 旧系统降级为只读
3. 新 PostgreSQL 成为 Source of Truth
4. Adapter 切换到 PostgresNativeAdapter
5. 观察 24 小时
6. 如无问题，开始下线旧功能
```

## 5. 数据迁移工具

### 5.1 历史数据迁移

```python
class HistoricalDataMigrator:
    """历史数据迁移"""
    
    async def migrate_students(
        self,
        batch_size: int = 100
    ):
        """迁移学生数据"""
        
        offset = 0
        while True:
            # 从旧系统批量读取
            students = await self.legacy_adapter.list_students(
                limit=batch_size,
                offset=offset
            )
            
            if not students:
                break
            
            # 写入新系统
            for student in students:
                try:
                    await self.postgres_repo.create_student(
                        external_student_id=student.id,
                        name=student.name,
                        student_no=student.student_no,
                        source_system="legacy_mysql",
                        source_updated_at=student.updated_at
                    )
                except IntegrityError:
                    # 已存在，跳过
                    logger.info(f"Student {student.id} already exists")
            
            offset += batch_size
            logger.info(f"Migrated {offset} students")
```

## 6. 风险与应对

### 6.1 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据映射错误 | 高 | 充分测试，数据对比验证 |
| 性能下降 | 中 | 双写异步化，建立索引 |
| 旧系统依赖 | 中 | 逐步解耦，Adapter 隔离 |
| 数据不一致 | 高 | 自动对比，告警 |

### 6.2 回滚方案

**阶段一回滚**：
- 关闭新系统
- 继续使用旧系统
- 无数据损失

**阶段二回滚**：
- 停止双写
- 新系统降级为只读
- 旧系统恢复为主系统

**阶段三回滚**：
- 紧急情况可切回旧系统
- 需要同步期间的新数据
- 需要数据修复
