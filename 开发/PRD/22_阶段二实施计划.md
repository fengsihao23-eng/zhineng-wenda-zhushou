> 本文只计划成绩数据接入。数据导入通过前，不允许把测试数据或旧产物当作全市真实数据。

## 1. 阶段目标

建立可重复、可审计、可回滚的学校成绩数据接入能力，优先支持 CSV/Excel 每日同步，保留数据库/API 适配器扩展点。

## 2. 输入文件与统一字段

首批文件固定为：

```text
schools.csv
students.csv
classes.csv
exams.csv
subjects.csv
student_exam_scores.csv
student_subject_scores.csv
question_scores.csv
```

每个文件必须含 `source_system`、`batch_id`、`external_id`、`school_external_id` 和原始行号；成绩文件额外要求学生、考试和科目外部 ID。正式表生成内部 UUID，禁止导入文件覆盖 `school_id` 或 `student_id` 的权限边界。

## 3. 导入流程

```text
上传文件
  → staging 表保存原始行和哈希
  → 表头、类型、必填项校验
  → 学校/学生/考试归属校验
  → 重复、冲突、引用完整性检查
  → 事务内幂等写入正式表
  → 失败行隔离并生成报告
  → 写入同步批次和审计日志
```

### 3.1 幂等与一致性

- 以 `source_system + external_id` 作为业务唯一键；原始行哈希相同则跳过，哈希变化则进入更新策略。
- 同一批次任一关键引用失败时，该行不得写入正式表；不允许半行成绩进入查询库。
- `school_id`、`student_id`、`exam_id` 必须通过同校约束；所有查询带学校范围条件。
- 导入是源系统到本系统的单向同步，学生端和模型层不得修改成绩事实。

### 3.2 适配器接口

定义统一 `StudentDataAdapter`，至少包含 `get_student`、`list_exams`、`get_exam_summary`、`get_subject_scores`、`get_question_scores`。CSV/Excel、只读数据库和只读 API 均实现同一接口，业务 Tool 不感知数据源。

## 4. 管理与可观测性

- 每个批次记录文件名、来源学校、行数、成功数、失败数、开始/结束时间和操作者。
- 失败报告按行号返回机器可读错误码，不回显数据库异常。
- 管理员可查询批次状态、重新执行失败批次和下载报告；重试必须保持幂等。
- 数据查询响应包含 `data_as_of` 和 `sync_batch_id`，便于学生和运营人员识别数据新鲜度。

## 5. 阶段验收

- [ ] 同一文件重复导入不会产生重复学校、学生、考试或成绩。
- [ ] 乱序导入和重复上传均能得到确定结果。
- [ ] 错误文件可定位到行、字段和错误码，并且不污染正式表。
- [ ] 学生、考试、成绩跨学校关联会被拒绝。
- [ ] CSV/Excel 导入与至少一个只读 Adapter 返回相同领域对象。
- [ ] 批次、审计和数据更新时间可查询。
- [ ] 导入 10 万条成绩的耗时、内存和失败率有实测记录。

未满足这些条件，状态保持 `in_progress`；“导入脚本能运行”不等于数据接入完成。
