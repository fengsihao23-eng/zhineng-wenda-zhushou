# 学科智能问答 · 微信小程序

原生 WXML / WXSS / JavaScript 实现，与 `apps/web` 共用 `apps/api`、学校账号、数据库和权限。范围依据用户 2026-10-20 提供的《学科智能问答小程序_高保真原型(1).html》。

## 当前公司内测路线（2026-10-21）

用户已购买新服务器，现阶段继续连接原服务器，先由个人主体注册小程序进行公司内部测试。原生预览需要先取得有效 AppID，再核验该账号的开发预览、成员访问和手机网络权限；当前 `touristappid` 不能生成可交付同事的有效原生体验码。

个人主体正式发布 AI 问答存在类目限制：腾讯官方目前说明深度合成类目仅向非个人主体开放。开发预览／体验权限也需按实际后台核验，不能将内部开发配置视为已通过发布审核。[官方说明](https://docs.cloudbase.net/ai/release/algorithm-filing)

注册、手机验证、AppID配置及同事验收的操作顺序见 [公司内测准备与扫码验收](../../docs/08-运维与交付/公司内测准备与扫码验收-20261021.md)。

## 在微信开发者工具中打开

1. 导入目录：仓库内的 **`apps/miniprogram`**。不要导入仓库根目录。
2. 尚无 AppID 时，选择开发者工具的“无 AppID／测试号”入口；不使用云开发。
3. 当前开发配置连接现有网页的正式后台数据。在仓库根目录执行：

   ```bash
   npm run mini:configure -- --api http://43.161.195.51/api/v1 --local
   npm run mini:check
   ```

   上述 HTTP 地址用于开发者工具联调，读取的是现有网页的业务数据，模型使用正式后台的 DeepSeek Flash。命令生成仅保存在本机的 `project.private.config.json`，暂时关闭开发环境域名校验。正式手机版本必须换成已配置的 HTTPS 域名。隔离自动化测试使用的 `127.0.0.1:8048` 是另一套测试库和测试模型，不能作为真实模型接通的证明。

4. 点击“编译”，使用学校提供的教师／学生账号登录。首次登录需要输入当前密码并设置新密码。家长沿用子女的学生账号。
5. 真机中的 `127.0.0.1` 指向手机，不能访问 Mac。真机验收需配置可访问的 HTTPS 域名；同一局域网调试可按微信文档使用 Mac 的局域网地址。

当前提交使用 `touristappid` 和现有后台的 HTTP 联调地址；正式体验版及发布前必须完成下方配置。

## AppID 与 HTTPS 配置

1. 打开 [微信公众平台](https://mp.weixin.qq.com/)，注册或使用已有的“小程序”账号。注册主体、邮箱验证、管理员扫码与认证由账号持有人完成。
2. 在小程序后台的开发设置中找到 AppID，并将操作者添加为开发成员。AppID 可以用于项目配置；本项目学校账号登录不需要 AppSecret。
3. 为现有 FastAPI/Web 服务准备固定 HTTPS 域名，部署本分支并执行数据库迁移至 `025_answer_usage_presence`。沿用现有模型网关、数据库和账号，不创建第二套业务库。
4. 在“小程序后台 → 开发 → 开发设置 → 服务器域名”中配置同一域名的 **request 合法域名**和 **downloadFile 合法域名**，例如 `https://qa.example.com`；这里不要带 `/api/v1`。域名、备案、证书和 TLS 要求以 [微信网络文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html) 为准。
5. 执行：

   ```bash
   npm run mini:configure -- --appid wx你的真实AppID --api https://你的域名/api/v1
   npm run mini:check -- --release
   ```

6. 关闭开发环境的“不校验合法域名”选项，在开发者工具和真机分别走完验收，再上传体验版。提交审核及发布由账号管理员完成。

`mini:check -- --release` 会拦截测试 AppID、本地 HTTP 地址、关闭域名校验等未完成配置。

## 实现范围

| 原型功能 | 小程序 | 网页同步与管理员入口 |
| --- | --- | --- |
| 原账号登录、首次改密、退出 | 登录／首次登录 | 共用 `/auth/*`，身份和权限由后台识别 |
| 自然语言提问、追问、澄清、分数表、来源 | 问答 | 网页 `/chat`、`/teacher/chat` 使用同一 `/answer-workbench/mini/ask` |
| 历史会话与继续提问 | 学习工具 → 历史会话 | 同一账号的持久化会话 |
| 诊断／作文报告搜索、筛选、逐页预览、下载 | 学习工具 → 报告中心 | 既有报告管理及考试开放设置；每次文件访问重新鉴权 |
| 人工留言、回答反馈、可选上下文 | 留言／回答下方入口 | 网页“提示词及人工 → 人工留言”（`/admin/prompts`） |
| 领取、草稿、核对回复、追加、关闭 | 用户看回复、追加、确认结束 | 网页管理员领取、查询、回复；教师继续沿用既有范围 |
| 身份、当前查询范围、报告操作记录 | 我的 | 来自同一后台 |
| 每日剩余次数、拥堵提示 | 输入框上方 | 两端共用服务端额度和在线状态 |

两端进入前台、切换业务页面及提交后读取最新数据；处于前台时每 30 秒同步。账号停用、授权撤销、报告版本变化会重新核验历史答复及来源。报告已打开时检测到变化会清空页面图片；已下载到用户设备的文件按原型提供保存能力。

### 每日额度

- 每账号每天 **100 次**，网页和微信端合计，上海时间 **00:00** 恢复。
- 服务端原子预占；同一请求标识的重试不重复扣次。多个设备争抢最后一次时最多一个成功。
- 正常回答、澄清、无授权和缺资料答复计次；模型故障、配置不可用及事务保存失败不计次。
- 次数用尽仍可查历史、看报告、下载报告、提交及办理留言。
- 网络响应丢失时保留问题与请求标识，可重试读回已保存结果。

### 在线人数

- 统计同一后端当前在线的已登录人数，包含网页和微信端；同一账号多个页面／设备只计一人。
- 前台每 30 秒续期，离开时释放当前客户端记录；异常断开最长 90 秒自动过期。
- 少于 500 人不显示；500–999 人“较为拥堵”；**1000 人及以上“极度拥堵”**。1000 人边界沿用附件中 `congestionLevel()` 的明确实现。
- 统计与额度使用数据库，多个 API 进程共用数据，服务重启不会清空今日额度。

## 验证

```bash
npm run mini:check
# 微信开发者工具开启“设置 → 安全设置 → 服务端口”后：
npm run test:mini:devtools
```

在隔离自动化测试前，应明确将 API 切回 `http://127.0.0.1:8048/api/v1`，并启动专用测试服务。正式数据补验脚本 `tests/miniprogram/live-backend.mjs` 要求显式提供所有者授权的短期验收会话文件，不在 CI 中自动对正式环境提问。

正式账号界面补验：先连接正式后台，由账号持有人在开发者工具中正常登录已有学生账号，再执行：

```bash
QA_WECHAT_LIVE_UI=1 npm run test:mini:live-ui
```

此命令实际输入并发送一条带“界面联调核验”标记的问题，保留正式会话并消耗 1 次当天额度。它核对模型回答、已授权成绩来源、同一网页 API 的保存结果、历史重开及额度；不读取或导出登录凭据，不退出持有人的登录。含业务数据的截图和证据仅写入被 Git 忽略的 `.local/wechat-live/` 私有目录。

测试环境、测试范围及当前未完成的人工环节见 [验收与上线说明](../../docs/06-QA与验收/微信小程序-20261020/验收与上线说明.md)。自动化 SDK 仅是根目录开发依赖，小程序运行包没有第三方 npm 依赖。

报告下载调用 `wx.downloadFile` 后使用 `wx.openDocument({showMenu:true})`，便于用户通过微信原生菜单保存。见 [微信文件 API 文档](https://developers.weixin.qq.com/miniprogram/dev/api/file/wx.openDocument.html)。
