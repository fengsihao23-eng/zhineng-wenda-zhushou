# 报告管理 r86 / 原型 v4 对齐与验收

日期：2026-10-19（北京时间）。范围：报告管理及其教师、学生 PDF 查询衔接。

个人操作步骤见 [验收路线](验收路线.md)。

## 对齐依据与已确认取舍

依据用户提供的 `业务流程图_V1(5).html`、`报告管理_高保真原型(1).html`，截图指定的「③ 报告管理 → 报告维护」范围。

两份 HTML 的上传约束不同：流程图允许多科、文件名辅助；原型为每批单科、规范命名后预填归属。用户明确选择 **以高保真原型为准**，因此采用后者。两份原文件仅在本地参考目录保存，不把其内嵌师生样例上传到公开仓库。

| 项目 | 实现 |
| --- | --- |
| 导航、页面 | 考务管理链接、报告维护、操作记录；页面色值、表格、筛选、抽屉和三步上传取自原型 v4，并限制样式作用范围 |
| 报告分类 | 个人学情、班级综合、班级单科、年级综合、年级单科、全校学情六种诊断；语文或英语个人作文批改 |
| 上传 | 先选择考试、类别、类型、单科范围；下载命名 CSV；PDF、文件名、考试参试归属校验；逐份预览、调整；清单预览后统一保存 |
| 识别规则 | 学生ID或唯一账号＋姓名定位；班级、年级取保存的考试名单；文件名不触发覆盖；同名学生可区分 |
| 重复与失败 | 考试＋类别＋类型＋科目集合＋对象唯一；列出本批和已存重复；失败事务回滚；重复请求使用提交回执避免重复办理 |
| 替换 | 保留报告身份与归属，要求有效新 PDF、实际预览、原因和确认；当前入口切到新版；历史版本仅管理端可访问 |
| 删除 | 可跨页勾选、批量核对、填写原因、确认；整批执行；删除全部可访问 PDF 版本并保留操作元数据 |
| 权限 | 使用已有考试显式授权；教师整体报告须覆盖全部对象和科目；学生仅查本人已开放范围的个人报告；不自动授权 |
| 查询端 | 「考试成绩与报告」显示具体报告类型、对象、科目和版本；支持实际 PDF 预览与下载；只返回当前版本 |
| 历史与并发 | 保存上传时的考试归属与覆盖范围；学生后续状态变化仍按可登录账号及历史考试授权查询报告；考试 revision、报告 version 和数据库唯一索引防止旧提交覆盖新状态 |

## 可复跑命令

```bash
cd apps/api
APP_ENV=test MODEL_PROVIDER=fake ../../.venv/bin/python -m pytest tests/test_report_management.py -q --no-cov

cd ../web
npm run lint
npm test -- --run
npm run build
```

真实浏览器测试复用考务验收的隔离运行器，指定专门的可丢弃数据库，名称须包含 `exam_v17_browser`。不要使用线上数据库：

```bash
QA_EXAM_DATABASE_URL='<隔离 PostgreSQL 的 asyncpg URL>' \
QA_EXAM_SPEC=report-r86.spec.ts \
node tests/education/run-exam-v17.mjs
```
