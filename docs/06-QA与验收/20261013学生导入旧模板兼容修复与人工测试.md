## 人工测试路线

测试前先更新到包含本次修复的版本，使用学校管理员账号和未导入这批账号的测试学校，记录学生列表当前总数。进入“业务生产 → 师生班级与考试 → 学生档案 → 导入学生”，选择本次反馈的脱敏 `.xls` 原文件，点击“开始预校验”，确认显示“预校验通过，共 16 行”，且学生总数尚未增加；点击“下一步：同班同名确认”，如出现提醒则逐行核实并保留本次应导入的学生，随后点击“确认入库”，确认回执显示“成功 16 条、放弃 0 条”。关闭回执，按文件中的账号查询学生，打开“查看档案”，核对姓名、账号、年级、班级和其他资料，确认生成学生ID，列表总数增加 16。再上传同一文件，确认提示“已有学生账号重复”、下一步按钮不可用且总数不再增加。最后复制一份模板，将“姓名”和“账号”两列交换后上传，确认错误原因明确指出第 5、6 列的差异，能下载错误清单，且未写入学生；另下载现行模板填写一条姓名、唯一账号和“正常”状态的数据，确认 `.xlsx` 的预校验及入库也正常。保留预校验、成功回执、档案详情及两类拦截截图用于汇报。

如果测试学校已经存在文件中的账号，上传后出现账号重复是正确结果。兼容表头不会允许同一账号重复新增学生。
