## 完整业务链路

在独立的合成验收学校中执行了下列操作，原学校 160 名教师未被删除、停用或改密：

1. 与原文件同格式的教师资料导入、自动建号、角色生成、首次登录拦截和改密；改密后的旧令牌失效。
2. 空姓名、空账号和非法状态合并到同一行错误清单，下载实际 Excel 错误文件。
3. 同姓名/年级/学科的疑似重复教师默认保留；逐条核对，一条保留、一条放弃；未核对时禁止确认。
4. 有任教关系的教师删除被拦截；移交 6 条任教授权后删除成功，再用同一账号和变更后的资料重新导入。
5. 无关联教师的停用、删除、重导；考试管理员离职后令牌无法继续使用。
6. 学生 30 列 Excel 导入；导入不建立家长绑定，学生档案也不提供绑定/解绑入口（该功能已按产品决定移除）。
7. 无成绩学生先删除后重导，通过修改年级/班级列从高中一年级 1 班调到 2 班。
8. 有成绩学生删除被拦截；毕业停用后，总分、学科分、小题分、会话和 4 条消息仍存在。
9. 普通教师、双学科备课组长、年级长、学校管理员、考试管理员权限，以及跨校批次读取边界。
10. 真实模型回答、流式输出、页面刷新后的历史回读和模型调用日志。

## DeepSeek Flash 配置与实测

官方文档当前推荐的模型标识为 `deepseek-flash`，API Base 为 `https://api.deepseek.com`。本次先调用官方 `/models` 验证密钥和可用模型，再执行真实 Chat Completions 请求及应用内问答。

配置：`MODEL_PROVIDER=deepseek`、`DEEPSEEK_MODEL=deepseek-flash`、`DEFAULT_MODEL=deepseek-flash`、`DEEPSEEK_THINKING=disabled`。采用非思考模式以适配当前基于确定性数据工具的即时问答；回复上限使用现有 `MAX_TOKENS`。Provider 普通/流式调用都发送对应 thinking 参数。

本地虚拟环境原先实际安装的 OpenAI SDK 为 1.10.0，与仓库声明不一致；已安装符合现有依赖约束的 1.109.1，消除其与 httpx 0.28 的初始化兼容问题。

密钥只保存在 Git 忽略的 `.env` 和 `apps/api/.env`，文件权限为 0600；未写入源码、验收报告或浏览器资源。Docker Compose 同步提供模型及 thinking 的环境变量传递。

真实验证结果：

- 官方模型列表请求 HTTP 200，包含 `deepseek-flash`。
- 连接测试请求 HTTP 200，回复「连接成功」。
- 应用内问题「我这次数学考试多少分？请只根据查到的数据回答。」返回 **83 / 100**，并明确排名和均分无数据。
- 该回答附有 1 条数据来源，API 全程约 1.35 秒；模型调用日志记录 Provider 为 `DeepSeek`、模型为 `deepseek-flash`，输入 367、输出 58、合计 425 tokens，模型调用耗时 1,241 ms。这是一次样本，不是性能基准。
- 后续小题丢分问答通过 SSE 完成；页面刷新后可读取此前回答。

模型联调使用独立测试学校的合成学生、83/100 分成绩和第 1 题丢 2 分。真实教师个人资料没有发给模型。

官方依据：[首次调用 / 模型名称](https://api-docs.deepseek.com/)、[思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode)、[模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)，核对日期 2026-09-22。
