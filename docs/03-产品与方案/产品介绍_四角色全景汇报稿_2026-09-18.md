# 学习智能中枢
## 四角色全景产品介绍与产品经理汇报稿

**汇报版本**：2026-09-18
**产品名称**：学习智能中枢  
**产品形态**：学生学习端 + 教师教学工作台 + 学校教务管理台 + 市级运营中心  
**当前演示环境**：隔离 QA 合成数据、Fake Model Provider、本地 OCR；不代表生产数据和真实模型质量。

---

## 一、产品介绍

知行学习智能中枢把学校的**师生、班级、考试、成绩、试卷、题库、报告和人工服务**连接在一起，为学生提供可信的学习数据和智能问答，为教师提供授权范围内的班级分析和学生跟进，为学校提供完整的教务生产与数据治理工作台，为市级运营人员提供跨校运营、风险和服务质量视图。

产品核心不是单独做一个聊天机器人，而是建立一条完整的学习业务链：

```text
学校数据接入
  → 成绩/试卷/题库生产
  → 教师分析与学生学情
  → 学生错题复习与智能问答
  → 来源追溯与人工服务
  → 学校、市级运营和风险治理
```

系统通过四个角色空间承载不同工作目标，但共享同一套身份、数据范围、来源、状态和审计规则。

---

## 二、产品要解决的问题

当前学校的学习数据通常分散在教务系统、成绩表、试卷文件、题库、诊断报告和人工沟通渠道中，造成几个具体问题：

1. 成绩导入依赖脚本或人工处理，字段错误、重复导入和账号绑定不容易追踪。
2. 试卷原件、拆题结果、题库正文和学生小题得分之间缺少稳定关联。
3. 学生能看到分数，但不一定能打开原题、解析、报告原件或形成复习记录。
4. 教师只能看到零散成绩，难以按授权班级、学科和考试查看知识点失分与学生详情。
5. 学生发起求助后，老师回复、处理过程和学生确认缺少统一的双向记录。
6. 管理人员能够看到风险或反馈数量，但不一定能继续完成处理和回读。
7. 模型回答如果没有固定考试范围、来源版本和数据权限，容易出现数据混淆或越权风险。

知行的设计目标是把这些工作放回同一个业务平台中，并且让每个重要结论都有明确的数据来源和权限依据。

## 三、产品总体结构：一套底座，四个空间

| 空间 | 主要用户 | 核心目标 | 数据范围 |
|---|---|---|---|
| 学生空间 | 学生 | 看成绩、看趋势、看报告、复习错题、向助手提问、获得人工帮助 | 本人数据、本人被授权的报告和正式学习资料 |
| 教师工作台 | 教师 | 查看任教班级分析、跟进学生、处理人工转接、处理风险和反馈 | 本校有效任教班级与学科；个体下钻单独受权并留痕 |
| 学校管理台 | 学校管理员 | 管理师生班级、考试学科、成绩导入、试卷、题库、报告和学校运营 | 本校业务数据与治理数据 |
| 市级运营中心 | 市级运营人员 | 查看跨校接入、风险、反馈、人工服务和知识治理 | 跨校汇总与运营范围数据，默认不直接开放学生明细 |

四个空间共享以下产品基础能力：

- 登录、角色和租户隔离。
- 学校、班级、学科、考试和任教范围控制。
- 数据来源、来源版本、更新时间和内容哈希。
- 加载、空状态、错误、无权限和重复提交反馈。
- 操作回执、状态流、幂等键和服务端回读。
- 会话、Trace、Prompt 版本、Tool 记录和 Response Guard。
- 学生问答中的考试/学科上下文与证据下钻。
- 桌面管理工作台和学生移动端适配。

## 四、学生空间：让学生从“看到分数”走向“理解并行动”

学生空间的核心路径是：

```text
学习总览
  → 成绩概览 / 趋势
  → 诊断报告 / 错题
  → 原题与解析
  → 订正与复习
  → 智能问答或人工帮助
```

### 4.1 学习总览

入口：`/`

学生登录后首先看到最近学习状态，包括：

- 学生身份和当前数据状态。
- 最近一次考试总分。
- 班级排名和年级排名。
- 与上次考试的分数变化。
- 正式诊断报告数量。
- 风险与老师跟进数量。
- 最近一次考试的科目表现。
- “问问学习助手”快捷入口。

产品价值：

- 让学生先知道“当前发生了什么变化”，再决定进入成绩、错题、报告或问答。
- 页面显示数据是否已同步、是否可追溯，不用装饰性文案代替真实数据状态。
- 没有考试数据时显示空状态，明确提示需要完成考试或等待数据接入。

### 4.2 成绩概览

入口：`/profile`

提供最近一次考试的成绩概况：

- 总分、满分和得分率。
- 班级排名、年级排名。
- 各科成绩和得分率。
- 雷达图或科目表现图。
- 与上次考试的变化。
- 数据更新时间和成绩来源状态。

目前保留了新系统已经修复的响应式图表、未知满分处理和身份隔离缓存。

### 4.3 成绩趋势

入口：`/trends`

提供跨考试的变化观察：

- 总分趋势折线图。
- 每次考试的分数、日期和变化值。
- 各科连续变化。
- 缺少满分时不伪造得分率。
- 没有足够考试记录时显示基准或空状态。

产品价值是帮助学生回答“我是在进步还是退步”，而不是只展示一个孤立分数。

### 4.4 诊断报告

入口：`/diagnosis`

学生可以查看被授权的正式诊断报告：

- 报告摘要。
- 优势表现。
- 优先提升方向。
- 知识点信息。
- 行动建议。
- 报告来源、生成时间和版本。
- 报告原文查看。
- 报告原件和历史版本入口。

诊断报告的权限由同一套服务端规则控制：

- 当前学生必须是报告本人。
- 报告必须是正式状态。
- 报告必须处于有效授权范围。
- 授权可以按学生、考试、报告或学科范围控制。
- 授权撤销或过期后，页面、Tool 和原件读取都会拒绝。

产品原则：诊断结论来自正式报告。模型可以解释已有报告，但不能因为学生分数低就自行生成“薄弱点”“粗心”“基础不牢”等诊断。

### 4.5 错题分析、原题和复习

入口：`/mistakes`

错题页面提供：

- 累计丢分。
- 错题数量。
- 单题最高丢分。
- 按科目筛选。
- 考试、科目、题号、得分、满分和丢分。
- 答题状态。
- 查看原题/加入复盘。

进入原题后可以看到：

- 正式题目版本。
- 父级材料或大题内容。
- 题干和选项。
- 参考答案。
- 解析。
- 题目版本和来源信息。

加入复盘后可以保存：

- 订正内容。
- 复习笔记。
- 自评掌握状态：学习中、需要复习、自评已掌握。
- 下次复习时间。
- 多次复习历史。

产品原则：

- “丢分事实”和“掌握判断”分开保存。
- 失分不自动等于未掌握。
- 同一题不同考试的记录保留独立历史。
- 没有正式题目版本时，明确显示来源缺失，不用题号或模拟题干冒充原题。

### 4.6 智能问答

入口：`/chat`

学生可以围绕本人考试数据进行问答，例如：

- 这次考得怎么样？
- 我的数学是多少分？
- 比上次进步了吗？
- 哪几道题丢分最多？
- 报告说我应该重点关注什么？
- 这条成绩来自哪里？

问答页面具备：

- 多会话列表。
- 新建会话和结束会话。
- 当前考试选择。
- 当前学科选择。
- 中文输入法安全处理。
- 停止、重试和断线恢复。
- Markdown 和数学公式安全呈现。
- 回答来源卡片。
- 来源事实和版本下钻。
- 单条回答反馈：有帮助、需改进、数据有误、内容不合适。

问答的事实边界：

```text
模型负责：理解问题、组织语言、解释事实。
代码负责：分数、排名、变化、得分率、权限、权益和来源。
```

每条回答会保存：

- 会话和消息。
- Agent Run。
- Prompt 版本。
- Tool 调用。
- 来源证据。
- 模型和耗时信息。
- Response Guard 结果。

当前预览使用 Fake Provider，回答链路和证据链是真实的，但不代表真实模型质量验收。

### 4.7 家长与支持

入口：`/support`

学生可以：

- 发起家长授权申请。
- 查看授权状态。
- 提交回答反馈。
- 发起人工转接。
- 查看工单状态和处理说明。
- 向老师补充消息。
- 查看老师回复。
- 确认问题已解决或带原因重新打开工单。

当前已经实现的是“学生发起授权和服务请求”的基础闭环。家长独立身份、实名核验、监护关系消费和家长门户仍属于后续能力，不能把分享码当作家长身份认证。

## 五、教师工作台：从“看列表”走向“按教学范围分析和跟进”

教师工作台的核心目标是帮助教师回答：

- 哪些班级和学科需要关注？
- 哪些知识点失分集中？
- 哪些学生需要进一步查看？
- 学生的问题是否已经被跟进？

### 5.1 教师总览

入口：`/teacher`

页面包括：

- 当前授权范围内的学生数。
- 待处理风险数。
- 待处理反馈数。
- 人工转接数。
- 学生学情队列。
- 风险、人工转接和反馈待办队列。

教师只能看到当前有效任教关系允许的数据。没有配置任教关系时，系统默认显示空范围，而不是把全校数据开放给教师。

### 5.2 班级学科分析

入口：`/teacher/analysis`

教师选择：

- 班级。
- 学科。
- 考试。

系统返回：

- 样本量。
- 班级平均分。
- 最低分和最高分。
- 得分率分布。
- 与上次可比较考试的平均变化。
- 知识点失分聚合。
- 小题数量。
- 涉及学生样本量。
- 未映射知识点的小题数量。
- 匿名学生列表和授权学情下钻入口。

统计说明：

- 多标签题目会按标签分别统计，标签统计不能简单相加为总丢分。
- 掌握状态不会由班级分数自动推断。
- 上次考试只有在满分和样本口径可比时才给出平均变化。
- 教师下钻学生详情会记录审计事件。

### 5.3 学生学情

入口：`/teacher/students`

教师可以在任教范围内查看学生队列，并进入：

- 任教学科成绩。
- 小题丢分事实。
- 题目版本关联情况。
- 学生风险和跟进状态。
- 与学生的人工服务记录。

普通教师不会无条件看到学生总分、其他学科或其他班级数据。学校管理员可以查看本校授权范围内更完整的学生详情。

### 5.4 人工转接

入口：`/teacher/handoffs`

教师可以：

- 查看待接单和处理中的工单。
- 查看学生问题摘要和授权上下文。
- 接单。
- 回复学生消息。
- 填写真实处理说明。
- 关闭或重新打开工单。
- 查看全部处理记录。

工单状态是受控状态流，不允许任意修改字符串状态：

```text
open → accepted → resolved/closed
resolved/closed → 带原因重新打开
```

### 5.5 风险事件

入口：`/teacher/risks`

教师可以：

- 查看风险事件。
- 确认事件。
- 填写处理说明。
- 标记解决或关闭。
- 对已关闭事项重新打开并记录原因。

风险事件只是需要处理的运营记录，不代表系统自动给学生下结论，也不代替心理、医疗或学校正式处置流程。

### 5.6 反馈运营

入口：`/teacher/feedback`

教师可以查看学生对回答的反馈：

- 有帮助。
- 需要改进。
- 数据有误。
- 内容不合适。

反馈具备状态、责任人、处理说明和重复提交控制，可以进入学校运营队列继续处理。

## 六、学校管理台：把教务生产流程真正放回系统

学校管理台是本产品最核心的生产空间。它不只是查看统计，而是负责把学校数据生产成学生和教师可以使用的学习资产。

### 6.1 学校总览

入口：`/admin`

页面包括：

- 本校学生总数。
- 待处理风险。
- 待处理反馈。
- 人工转接数量。
- 学生学情队列。
- 风险、转接和反馈待办。

### 6.2 师生班级与考试

入口：`/admin/school`

工作台按对象分为：

#### 班级

- 查看班级列表。
- 外部班级标识。
- 新建原生班级。
- 停用班级。
- 停用前检查在籍学生和有效任教关系。
- 保留历史成绩，不做破坏性删除。

#### 学生与账号

- 查看学生外部标识、学号、班级和来源。
- 查看账号是否已绑定。
- 绑定现有学生账号。
- 检查同一账号多学生冲突。
- 不按姓名自动合并。

#### 教师账号

- 查看现有本校教师身份账号。
- 维护教师显示名称和状态。
- 教师账号管理与任教权限分离。
- 不在成绩导入时自动创建默认密码。

#### 教师任教

- 绑定教师、班级和学科。
- 设置开始时间和到期时间。
- 启用或停用任教关系。
- 任教关系直接决定教师能看到的班级和学科数据。

#### 学科

- 维护本校学科代码、名称和外部学科标识。
- 作为考试、成绩、题库、知识点和教师任教关系的关联基础。

#### 考试科目

- 管理考试名称、类型、日期和状态。
- 为考试配置学科。
- 配置学科满分。
- 已有成绩引用的满分不能直接修改，避免改变历史口径。

### 6.3 成绩导入

入口：`/admin/imports`

完整流程：

```text
上传 CSV
  → 选择或保存字段映射模板
  → 文件级/行级/字段级预检
  → 查看错误并修正原文件
  → 当前学校范围核对
  → 确认事务导入
  → 查看任务状态和回执
  → 单独完成账号绑定
```

系统支持：

- 固定文件类型和字段规范。
- 批次编号。
- 内容哈希。
- 映射模板版本。
- 学校范围检查。
- 学生、考试、学科、班级引用检查。
- 得分不能超过满分。
- 丢分必须等于满分减得分。
- 重复批次幂等。
- 批次内容冲突拒绝。
- 导入失败整批回滚。
- 逐行错误回执。
- 未绑定账号数量提示。

这个流程将“导入成绩”和“绑定登录账号”明确拆开，避免成绩进入系统后因为身份关系不清导致错人或串号。

### 6.4 试卷与原件

入口：`/admin/papers`

学校管理员可以：

- 上传 PDF、PNG、JPEG 原件。
- 校验文件签名和实际类型。
- 查看页数和文件大小。
- 绑定考试和学科。
- 查看原件版本。
- 替换原件并形成新版本。
- 查看内容哈希和来源。
- 受权预览或下载原件。
- 进入拆题工作台。

替换不会覆盖已经发布的历史版本，从而保证历史报告、题目和学生证据仍然指向当时的原件。

### 6.5 框选拆题工作台

入口：`/admin/papers/:paperId/split/:versionId`

工作台采用三栏布局：

1. **题目区域栏**：查看已框选题目、题目层级和区域数量。
2. **原图栏**：查看页码、缩放、原件和区域位置；支持鼠标框选和跨页区域。
3. **属性栏**：编辑题目层级、父级、题名、题干、选项、答案、解析、区域坐标和知识点标签。

任务状态：

- 草稿。
- 未保存修改。
- 已保存修订。
- OCR 排队/处理中。
- OCR 成功/失败。
- 人工确认。
- 正式发布。

OCR 结果不会直接覆盖人工草稿。操作者需要将识别结果放入草稿并再次核对，最后勾选确认后发布。

### 6.6 题库与知识点

入口：`/admin/questions`

题库层级：

```text
材料
 └─ 大题
     └─ 小题

独立题
```

题目版本可以保存：

- 题干。
- 选项。
- 参考答案。
- 解析。
- 试卷原件版本。
- 框选区域。
- 来源记录。
- 知识点和标签。

管理操作包括：

- 按学科、题型、层级、标题筛选。
- 查看父级和子级题目。
- 创建新版本。
- 人工确认发布。
- 批量软删除。
- 回收站恢复。
- 查看引用数量。
- 被成绩、复习记录或子题引用时阻断删除。
- 查看逐项操作回执。

### 6.7 知识点树与标签

知识点和标签使用同一题库入口管理，避免旧系统中多个知识点入口长期分裂。

支持：

- 知识点树。
- 学段、年级、题型、难度、能力和自定义标签类型。
- 父子节点校验。
- 防循环。
- 同学科绑定。
- 题目版本多标签绑定。
- 软删除。
- 引用保护。
- 恢复。

当前已经实现在线维护和引用保护；完整字典批量导入与大规模合并工具属于后续增强。

### 6.8 旧资料与来源

入口：`/admin/sources`

学校可以提交已批准的旧系统导出快照，系统会保存：

- 来源系统。
- 来源版本。
- 外部旧 ID。
- 新系统实体 ID。
- 来源内容哈希。
- 数据水位。
- 来源字段。
- 重放或冲突结果。

页面明确显示这是“受控快照”，不是实时旧库连接。旧整数 ID 不直接作为新系统主键使用。

### 6.9 班级分析和学生学情

入口：`/admin/analysis`、`/admin/students`

学校管理员可以查看本校范围内：

- 班级和学科考试聚合。
- 学生样本量。
- 知识点失分。
- 学生学科成绩。
- 小题丢分。
- 正式题目和报告来源。
- 学生服务跟进。

### 6.10 正式报告原件

入口：`/admin/reports`

管理员可以：

- 上传正式报告原件。
- 绑定学生、考试、学科和报告类型。
- 保存正式摘要。
- 保存报告原文。
- 形成版本。
- 查看原件。
- 区分学情诊断、成绩报告和批阅文件。

当前产品不把上传报告包装成 AI 自动批改，不会自动向学生开放诊断权益。

### 6.11 知识文档治理

入口：`/admin/knowledge`

学校管理员可以：

- 创建知识文档草稿。
- 编辑草稿。
- 提交审核。
- 审核通过或驳回。
- 驳回后返工。
- 发布。
- 下线。
- 查看来源、版本和处理状态。

当前知识文档治理是真实工作流，但**发布尚未接入课程 RAG 检索**。因此“已发布”表示文档治理状态，不表示已经参与线上问答。

### 6.12 反馈、风险和转接队列

学校管理台可以集中处理：

- 学生反馈。
- 风险事件。
- 人工转接。
- 状态迁移。
- 责任人。
- 解决说明。
- 审计历史。
- 学生回读。

所有关闭、解决、驳回、下线和重新打开操作都要求真实说明，避免出现固定“已完成核查”文案冒充处理结果。

## 七、市级运营中心：从跨校视角管理平台质量

入口：`/ops`

市级运营中心关注的不是单个学生的教务生产，而是全市平台是否接得上、用得稳、风险是否闭环。

### 7.1 市级总览

提供：

- 接入学校数。
- 待处理风险。
- 待处理反馈。
- 人工转接数量。
- 学校运行概览。
- 跨校待办队列。

### 7.2 学校运营

入口：`/ops/schools`

市级人员可以查看学校级汇总：

- 学校名称和编码。
- 在籍学生数量。
- 风险数量。
- 运行状态。
- 反馈和转接数量。
- 学校运营详情。

默认不展示学校内学生个人数据，避免把“跨校运营”直接等同于“跨校查看全部学生明细”。

### 7.3 知识库治理

入口：`/ops/knowledge`

市级运营可以处理跨校知识文档治理：

- 查看文档状态。
- 审核、发布、下线。
- 检查来源和版本。
- 处理跨校资料的运营状态。

当前仍需后续接入真实知识检索、学段/年级过滤、引用片段和下线传播验证。

### 7.4 反馈运营

入口：`/ops/feedback`

市级运营可以跨校查看：

- 回答有帮助率相关反馈。
- 数据错误反馈。
- 内容不当反馈。
- 处理状态。
- 责任人和解决说明。

### 7.5 风险事件

入口：`/ops/risks`

市级运营可以：

- 查看跨校风险数量和明细范围内的事件记录。
- 确认风险。
- 跟进处理。
- 记录处置结果。
- 重新打开需要继续处理的事件。

### 7.6 人工转接

入口：`/ops/handoffs`

市级运营可以查看跨校人工服务队列，了解：

- 工单量。
- 待接单和处理中数量。
- 处理状态。
- 处理说明。
- 服务闭环情况。

当前普通市级运营不自动获得学校教务写权限。平台超级管理员可根据明确授权进入学校业务工作台，但这是能力授权，不是默认市级权限。

## 八、六条核心业务闭环

### 闭环一：成绩从导入到学生查分

```text
学校上传成绩文件
  → 字段映射
  → 逐行预检
  → 修正错误
  → 批次确认
  → 事务写入
  → 账号绑定
  → 学生登录查分
```

结果：学校知道批次是否成功、哪些行失败、哪些学生尚未绑定；学生能够看到真实成绩和数据时间。

### 闭环二：试卷从原件到正式题库

```text
上传试卷原件
  → 绑定考试和学科
  → 框选区域
  → 编辑草稿
  → OCR 识别
  → 人工核对
  → 正式发布
  → 题目和版本被成绩引用
```

结果：题目、解析、知识点和学生得分拥有同一条来源链。

### 闭环三：学生从错题到复习

```text
小题丢分
  → 打开正式题目
  → 查看解析
  → 加入复盘
  → 填写订正
  → 自评掌握状态
  → 安排下次复习
```

结果：系统记录学生实际做过的复习动作，不把分数直接等同于能力结论。

### 闭环四：教师从班级分析到学生跟进

```text
选择任教班级/学科/考试
  → 查看样本、均分和分布
  → 查看知识点失分
  → 下钻授权学生
  → 进入人工服务或风险处理
  → 写入处理记录
```

结果：教师只在任教范围内工作，并能把聚合分析转化为具体跟进。

### 闭环五：报告从正式版本到证据下钻

```text
上传正式报告
  → 绑定学生/考试/学科
  → 保存原件和版本
  → 学生按权益查看
  → 查看报告原文/附件
  → 在问答中引用报告事实
```

结果：报告页面、问答 Tool 和原件预览使用同一权益规则，避免一个入口允许、另一个入口越权。

### 闭环六：学生求助到人工回复

```text
学生发起人工转接
  → 教师/管理员接单
  → 双向消息
  → 处理说明
  → 学生确认解决或带原因重开
```

结果：人工服务不再只是一个状态按钮，而是有消息、责任人、记录和学生侧进度。

## 九、产品亮点

### 9.1 数据可信

- 成绩和排名由代码计算，模型不能自行编数字。
- 题目、报告和原件有稳定版本。
- 来源卡可以下钻到具体事实。
- 导入、发布、状态更新和消息发送都有回执。

### 9.2 权限可信

- 学生只能看本人数据。
- 教师按照任教班级和学科过滤。
- 学校管理员只看本校。
- 市级默认看跨校汇总。
- 诊断报告额外受权益、时间和资源范围控制。

### 9.3 业务可操作

- 成绩不再只有脚本入口。
- 试卷不再只有文件上传。
- 错题不再只有题号和丢分。
- 人工转接不再只有“已完成”状态。
- 知识文档不再以“有页面”冒充已接入问答。

### 9.4 安全可回退

- 重复提交不会重复建题、建工单或写反馈。
- 版本冲突不会静默覆盖他人修改。
- 批次失败会整批回滚。
- 被引用题目不能误删。
- 已发布原件和报告版本不被覆盖。
- OCR 失败可以重试，也可以人工继续。

### 9.5 适合分阶段交付

产品不要求一次重建旧系统全部能力，而是按以下顺序演进：

```text
可信接入
  → 核心业务生产
  → 学生与教师闭环
  → 知识检索、家长门户和模型评测
```

## 十、建议的产品演示顺序

建议向产品经理进行 15–20 分钟演示。

### 第一段：学校管理员，展示平台生产能力

1. 进入学校总览，说明学校级数据和待办。
2. 打开“师生班级与考试”，说明师生、班级、教师账号、任教、学科和考试的关系。
3. 打开“成绩导入”，演示批次、映射、预检、逐行错误、确认和回执。
4. 打开“试卷与拆题”，上传原件并进入三栏工作台。
5. 演示框选、草稿保存、OCR、人工确认和发布。
6. 打开“题库与知识点”，展示层级、版本、标签和引用保护。
7. 打开“正式报告原件”和“旧资料与来源”，说明来源和版本。

### 第二段：教师，展示教学分析能力

1. 进入教师总览。
2. 进入班级学科分析，选择班级、学科和考试。
3. 查看样本量、平均分、分布、知识点失分。
4. 下钻一名授权学生。
5. 打开人工转接、风险事件和反馈运营。
6. 演示接单、回复和处理记录。

### 第三段：学生，展示学习闭环

1. 进入学习总览，看最近考试和科目表现。
2. 打开成绩概览和成绩趋势。
3. 打开诊断报告和正式原件。
4. 打开错题，查看正式原题和解析。
5. 加入复盘，填写订正和自评掌握状态。
6. 进入智能问答，选择考试和学科。
7. 查看回答依据、来源版本和反馈入口。
8. 在家长与支持中发起人工帮助，并回读老师消息。

### 第四段：市级运营，展示治理能力

1. 进入市级总览，说明跨校汇总。
2. 打开学校运营，查看学校接入和运行状态。
3. 查看跨校知识文档治理。
4. 查看反馈、风险和人工服务队列。
5. 说明市级运营默认不直接开放学校学生明细。

### 演示结束时的产品结论

> 学校管理员负责把数据和学习资产生产出来；教师负责在授权范围内分析和跟进；学生负责理解自己的学习情况并采取行动；市级运营负责保证平台接入、内容和服务质量。四个角色使用同一套可信数据和权限底座。

## 十一、当前实现边界：汇报时必须准确说明

### 已真实实现并通过隔离验收

- 四角色登录与路由守卫。
- 本人、任教班级、学校和市级数据范围。
- 成绩导入工作台和现有事务导入内核。
- 受控旧资料快照和来源映射。
- 师生、班级、教师账号、任教关系、考试和科目管理。
- 私有原件校验、版本、权限和预览。
- 题库层级、题目版本、知识点标签、发布、软删除、恢复和引用阻断。
- 真实本地 OCR、草稿自动保存、重试和人工发布。
- 错题原题、解析、复盘、订正和自评复习。
- 教师班级聚合、知识点失分和学生下钻。
- 报告版本、原文、原件和统一权益。
- 人工转接双向消息、处理记录和学生回读。
- 问答上下文、来源持久化、证据下钻和消息反馈。
- 移动抽屉、键盘焦点、中文输入和已有图表响应式回归。

### 已有入口但仍属局部能力

- 旧系统接入目前是受控快照，不是实时 Legacy Adapter。
- 报告和试卷原件目前存于私有数据库 Blob，对象存储和大文件容量方案待部署。
- 知识文档审核工作流已实现，但 RAG 检索尚未接入回答。
- 家长授权申请已实现，家长独立登录和监护关系消费未完成。
- 模型状态和 Prompt/Trace 底座保留，但完整配置评测、灰度和回滚工作台未完成。
- 问答是安全校验后的整段输出，不是逐 Token 实时生成。
- OCR 是本地引擎加人工确认，没有生成式 AI 自动拆题承诺。

### 当前明确不应宣称

- 不宣称已经替代旧系统。
- 不宣称真实旧数据已经完成迁移对账。
- 不宣称 Fake Provider 代表真实模型质量。
- 不宣称发布知识文档就已经可以被问答检索。
- 不宣称低分自动生成诊断结论。
- 不宣称学生分享码等于完成家长实名授权。
- 不宣称已经完成市级容量、灾备、法务和隐私评审。

## 十二、需要产品经理确认的下一步决策

### 12.1 旧系统接入策略

需要确定：

- 继续使用受控快照，还是建设旧 API/数据库只读 Adapter。
- 哪些业务域继续由旧系统写主。
- 哪些域切换到新系统写主。
- 来源版本、水位和对账的业务责任人。

### 12.2 原件存储策略

需要确定：

- 是否接入对象存储。
- 最大原件大小、保存年限、备份和删除策略。
- PDF、图片、报告和学生上传附件是否使用不同存储桶。

### 12.3 教师权限策略

需要确定：

- 教师是否可以查看同班其他学科的聚合。
- 个体下钻是否需要额外审批。
- 校长、年级组长和教研员是否新增独立角色。
- 任教关系的生效期由谁维护。

### 12.4 报告和诊断策略

需要确定：

- 哪些报告类型对学生开放。
- BASIC 与 DIAGNOSIS 权益是否保留。
- 诊断报告是否需要人工审核后发布。
- 报告过期、撤销和历史版本的学生展示规则。

### 12.5 知识库与模型策略

需要确定：

- 哪些学科和年级进入首批 RAG。
- 课程资料的审核人和失效时间。
- 真实模型 Provider、成本、限额和降级策略。
- 是否采用审核后完整输出，还是建设安全增量流。

### 12.6 学生学习功能优先级

建议优先顺序：

1. 正式题目和解析的覆盖率。
2. 订正和复习计划的使用反馈。
3. 教师跟进记录和学生回执。
4. 规则型相似题。
5. 审核知识库问答。
6. 个性化学习计划和长期学生画像。

## 十三、产品总结

知行的核心产品价值可以概括为三句话：

1. **对学生：** 把成绩、错题、报告和问答串成一条可理解、可复习、可追溯的学习路径。
2. **对学校：** 把成绩导入、试卷拆题、题库、报告和人工服务变成可以操作、可以回读的教务工作台。
3. **对平台：** 用角色、租户、来源、版本、审计和状态流把市级教育智能服务放在可控边界内。

最终产品不是四套互相独立的页面，而是一个以可信教育数据为底座的学习业务闭环：

```text
数据接入可信
  → 学习资产可生产
  → 教师分析可跟进
  → 学生复习可行动
  → 问答结果可解释
  → 运营风险可治理
```
