# 平台学生ID、教师ID编码规则（2026-10-12）

平台统一分配数字流水号，从 `10000001` 起，到 `9999999999` 止。当前为8位，随使用量增长可到10位。学生、教师共用一个全平台唯一的编号空间；编号不含学校、年级、年份、姓名、手机号等信息，只用于定位平台档案、数据关联和沟通检索。

| 字段 | 用途 | 变化规则 |
| --- | --- | --- |
| 学生ID / 教师ID | 平台身份及关联定位 | 平台生成，不可手改；已分配号码永久保留 |
| 登录账号 | 登录认证 | 按专用变更流程修改，与平台ID独立 |
| 学号 | 学校档案中的学号 | 普通档案字段，保留原值，与平台ID独立 |
| 中/高考号、准考证号等 | 对应考试或外部业务编号 | 保留原值，与平台ID独立 |
| 外部系统学生ID | 上游系统同步 | 保留独立命名及原值，不替代平台ID |

查阅方案后，本平台采用数据库流水号。PostgreSQL的序列支持多个会话并发取得不同编号，`MAXVALUE`和`NO CYCLE`可以限制长度并禁止循环；同时增加主键及唯一约束。[序列并发规则](https://www.postgresql.org/docs/15/functions-sequence.html)、[序列上限规则](https://www.postgresql.org/docs/15/sql-createsequence.html)、[Identity与唯一约束](https://www.postgresql.org/docs/17/ddl-identity-columns.html)。

UUID适合分布式技术标识，但常规文本形式长于本次10位要求；它继续服务于现有数据库外键和接口兼容。短ID通过永久映射定位同一份原档案，业务办理用短ID即可，无须改写历史成绩、报告或任教关系。[UUID标准](https://www.rfc-editor.org/rfc/rfc9562.html#section-4)。也核对了[Twitter原始Snowflake实现](https://github.com/twitter-archive/snowflake/blob/snowflake-2010/src/main/scala/com/twitter/service/snowflake/IdWorker.scala)；它把时间和机器信息合入长整数，本平台目前由同一数据库统一分配，采用流水号更符合短数字与沟通检索需求。

改名、换账号、升级换班、离校/毕业及同学段恢复在读均保留原学生ID。教师资料变更的专属任务保留原教师ID。教师纯删除后再次新增使用新ID；学生误导入删除后再次新增也使用新ID，原编号继续保留在映射与办理记录中。编号允许间断，不能根据人数推算下一个编号，也不能重置或循环复用。

档案列表、档案快照、变更预览、导入回执和变更模板使用短ID。学生、教师关键词检索支持短ID；教师删除记录也支持短ID查询。学生档案变更31列、升级换班5列、教师变更25列的ID列均导出短号。手工指定保留学生、批量身份核验、恢复班级和教师对应关系支持短ID。

后台按学校和身份类型核验ID，不会使用登录账号、学号或考号代替ID。学生ID与教师ID不能混用，其他学校的ID不能办理。旧UUID模板、待办任务和接口引用继续兼容；同一人在一个文件中同时出现旧UUID与短ID仍判定重复。对外JSON中的短ID按字符串传递，Excel导出为文本。

迁移 `020_short_person_ids` 回填已有学生、教师、历史删除快照及历史导入中的身份。技术主键、历史外键、账号、密码、学号、考号及原上传文件保留。旧任务原UUID与指纹保留，快照补充短ID。映射表及已分配编号受不可改写约束保护。应用回退时须保留这张映射表；禁止通过删除已发放的ID来回退数据。
