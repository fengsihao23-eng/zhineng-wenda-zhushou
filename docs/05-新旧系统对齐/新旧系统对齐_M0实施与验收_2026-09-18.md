实施范围：2026-09-17 提出的首批权限、安全和交互门禁；最终验证：2026-09-18。以当前工作区新系统为主，保留已有未提交修改。此报告不是旧教务系统全面替代声明，也不是生产上线批准。

| 生产演示隔离 | 真实实现 | Vite 生产构建不包含演示登录区；生产/预生产以及非明确 development/test 环境关闭示例账户，阻断已知示例身份/示例学校/旧默认密码；种子脚本限制开发测试环境。未替代正式统一身份接入。 |
| 可重启、多进程撤销 | 真实实现 | PostgreSQL 持久撤销摘要；每次认证查共享表，存储不可用返回 503，不回退内存。刷新凭据原子消费；退出撤销整个登录 `sid`，覆盖刷新前后的访问凭据。重复退出幂等，不能混用其他用户/会话凭据。数据库不保存原始 JWT。 |
| 退出与输入法 | 真实实现 | 明确“退出”操作，等待服务端撤销成功；失败保留状态并提示重试。中文组合输入、`isComposing`、WebKit 229、重复按键不触发发送；普通 Enter 发送，Shift+Enter 换行。 |

本轮业务路径没有新增 Mock 数据源。自动测试使用合成夹具；模型为明确 Fake Provider，浏览器故障场景使用受控错误响应，不能当作真实模型质量验证。

## 2. 权限与状态契约

### 路由/角色

- 学生：`/`、`/profile`、`/trends`、`/diagnosis`、`/mistakes`、`/chat`、`/support`。
- 教师：`/teacher/*`，新增正确的 `/teacher/feedback`。
- 学校管理、QA：`/admin/*`；QA 不因此获得全局 Prompt 写权限。
- 市级运营、超级管理员：`/ops/*`。
- 多角色账号后端按授予的最高数据能力处理。不能通过前端角色切换获得不存在的后端权限。

### 状态流

| 类型 | 合法迁移 |
|---|---|
| 风险 | open → acknowledged → resolved/closed；resolved → acknowledged/closed；closed → acknowledged |
| 反馈 | open → acknowledged/resolved/closed；acknowledged → resolved/closed；resolved → open/closed；closed → open |
| 转接 | open → accepted/closed；accepted → resolved/closed；resolved → open/closed；closed → open |
| 知识 | draft → pending_review → published/rejected；rejected 经实际编辑保存为 draft；published → offline → published |

解决、关闭、重新打开必须填写说明；驳回、下线必须填写原因。重复目标状态不改责任人/时间、不重复审计；不允许同状态重复请求覆盖原说明。写接口支持 `expected_version`，版本不符或 CAS 竞争失败返回 409。

## 4. 上线前必须执行（本轮未代为部署）

1. 运维先备份并在预生产复验，再执行迁移 `010_access_scope → 011_platform_states → 012_token_revocation → 013_operation_receipts`。现存非法状态/跨租户关联会阻止迁移，必须人工核对，不自动删除或改归属。
2. 学校数据负责人提供已审批的教师—班级—学科关系，写入 `teaching_assignments`。本轮没有新增任教授权管理 UI/API 或自动为旧教师授予全校权限。表中的班级引用 `import_classes.id`；现有学生可通过明确 `class_id` 或同校唯一 `external_class_id` 关联。未配置时教师看到空范围，这是安全默认值，不是导入失败。
3. 配置跨 worker 一致、稳定、独立的应用/JWT 密钥与同一个 PostgreSQL。所有旧无 `sid/session_exp` 凭据需重新登录。撤销表必须先存在再启动新 API。
4. 保留撤销记录至少到相应凭据/会话绝对到期；不能将撤销记录恢复到退出前的备份状态后继续信任旧凭据。当前未新增清理任务，后续需配置按到期时间清理，禁止截断整表。
5. 生产使用正常 production Web 构建，显式环境配置，禁止演示身份和默认密码。可将 API workers 调大，但限流等其他进程内能力尚需独立容量/部署评审，本轮撤销修复不等于全平台水平扩展验收。
6. 业务确认诊断授权语义（沿用 BASIC/DIAGNOSIS，不自行决定公共服务收费政策）、任教关系、风险处理职责。学校/未成年人保护代表尚未签署生产业务验收。

## 5. 保留与未承诺

保留：新系统鉴权与租户归属、确定性成绩 Tool、会话/幂等/取消、Trace、Prompt 版本、Response Guard、CSV 事务导入与错误回执、身份隔离缓存、既有响应式图表。

旧系统仅核对业务入口和交互：导航分组、人工会话列表/回复、报告原件预览。没有复制旧源码、启动旧业务服务或连接旧业务数据库。

未实现/未验证：完整题库/OCR/报告附件生产链、复盘订正、双向人工消息、班级知识点聚合、RAG、家长身份消费闭环、真实模型质量、业务环境性能与灾备、法务/隐私评审。现有 Prompt/Trace 等管理接口也不等于管理 UI 已交付。

普通已登录页面的既有成绩查询缓存仍保留；诊断原文打开/重新打开会重新核验权益，权限变更以服务端下一请求为准。本轮没有建设向已展示页面推送权限撤销的实时通道。

## 6. 复测注意事项

不要直接在项目含敏感配置的目录运行会自动加载环境文件的排查脚本。后端本轮从临时目录运行，显式指定隔离 `DATABASE_URL/TEST_DATABASE_URL`、`APP_ENV=test`、Fake Provider 与测试日志位置，再通过 `PYTHONPATH` 指向 `apps/api`。Pytest 的 `test_engine` 会清理测试表，**不得把业务库 URL 用作 TEST_DATABASE_URL**。

浏览器启动器固定连接名为 `qa_alignment` 的本机隔离 QA 库、55439 端口，并启动 8018 两 worker API / 5198 Web 测试代理。仅在创建并迁移该一次性测试数据库后运行 `node tests/alignment/run.mjs`。该运行器不是生产启动脚本；每次生成新的合成学校，测试结束关闭临时 API/Web 服务，不操作业务库。

本轮创建的容器为 `qa-alignment-p0-20260917`，仅含合成 QA 数据；交付时停止而不删除，避免残留运行服务，也保留复核条件。未停止或重启已有业务容器。
