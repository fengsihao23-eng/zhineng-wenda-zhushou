# 0922 师生档案流程落地说明

依据：仓库根目录 `0922业务流程图_教师批量导入（新增）_V1.html` 中「基础数据与权限 → 维护教师 / 学生档案」的四个子流程、关键规则和内嵌 Excel 附件。原 HTML 保持不变。

入口：学校管理台 → 师生班级与考试（`/admin/school`）→ 教师档案 / 学生档案。

本次补充仅依据 `0922业务流程图_教师信息变更（删旧 → 重导）_V1.html` 的第 2、3 页签，更新教师变更、学生新增及登录自动识别。学生新增同时兼容用户提供的 `阳江一中高中一年级学生资料模板0511.xls`；其他业务流程沿用原实现。

## 流程逐项对应

| 流程图要求 | 实现行为 |
| --- | --- |
| 教师统一 Excel 新增，不提供单个新增 | 教师档案提供模板下载、上传、预校验、预览、确认；不设单个新增表单 |
| 教师 24 列及固定列序 | 使用原 HTML 内嵌 `TPL_TEACHER` 附件，保留 4 条样例；解析时严格检查全部列名和顺序 |
| 文件级结构错误 | 整份拒收，只生成一条文件级错误，不进入行级校验 |
| 姓名、账号必填 | 检查教师姓名、教师账号；学工号不要求填写 |
| 账号查重仅限教师 | 同一学校教师范围内查库及文件内重复；教师与学生、家长同名不拦截；登录以账号和密码自动识别身份，去掉账号类型与学校 ID 输入 |
| 教师状态仅正常 | 非「正常」进入错误清单；离职和停用由列表独立操作 |
| 手机不校验、不查重 | 脱敏手机按原文保存在档案；不尝试还原手机号 |
| 教师班级非必填，不匹配也不拦截 | 解析 `科目:年级.班级,年级.班级;`；可解析且字典匹配时生成任教关系，未匹配参考写入回执，不进入错误清单 |
| 疑似重复教师 | 只比较已有教师：同姓名，任课字段至少一个同年级、同科目；班号和手机号不作为命中条件；任课字段为空不参与 |
| 命中默认保留并逐条确认 | 内联清单默认「保留」，管理员逐条核对，可改「放弃」；未核对完不能确认；服务端要求完整逐行决定 |
| 角色权限随导入生成 | 职务说明及班主任、备课组长、年级长、三个主任/校长标志生成数据库角色；按班级、学科、年级生成任教范围 |
| 初始密码等于教师账号，首次登录强制修改 | 建号时只存密码哈希；首次令牌仅可读身份、改密或退出；业务 API 和页面均拦截；修改后旧令牌失效 |
| 教师变更先删后导 | 支持姓名/账号、手机号、任教班级筛选；确认删除后重新上传同一 24 列模板；原直接编辑 API 返回 `ROSTER_REIMPORT_REQUIRED` |
| 教师删除保留历史 | 不再因任教关系拦截删除；原登录身份停用、释放账号名，保留原用户 ID 及全部历史外键和任教记录，重新导入创建新身份及最新权限 |
| 删除快照长期可查 | 保存原 24 列全部字段、删除人和时间；「教师删除记录与历史查询」支持按姓名 / 原账号查找，重导后仍可查看原资料和任教记录 |
| 教师重导密码规则 | 同账号自动关联待重导记录，账号变更时在预览指定原删除记录；已改密码保持原哈希，仍用初始密码时改为新账号并继续强制首登改密；删除记录只能消费一次，支持并发与事务回滚 |
| 学生统一 Excel 新增 | 使用原 HTML 内嵌 `TPL_STUDENT`，保留全部 49 条样例；支持用户提供的 `.xls` 与原 `.xlsx`，共用同一 30 列校验及整批入库规则；确认时同时创建登录账号与学生档案 |
| 学生 30 列 | 原列原值完整保存在 `profile_fields`；兼容原文件 mac地址 / SN码 列末尾空格 |
| 学生姓名、账号必填，账号唯一 | 按同校学生账号查重；内部主键使用 UUID，学号可留空，学籍号和考试号不当作档案主键 |
| 学生年级/班级必须匹配 | 文本年级名 + `N班` 对应本校有效且唯一班级；支持班级名称「高中一年级1班」或外部标识「10.1」；不匹配生成逐行错误 |
| 学生可选资料不做格式校验 | 身份证、手机、email、全国学籍号、住宿等原样保存 |
| 学生变更、调班先删后导 | 阻止单个新增和原地编辑 API；先删除无关联原档案，再改模板的年级、班级字段重新导入 |
| 学生删除关联拦截 | 检查成绩、错题、会话、报告等关联，存在则阻止；原档案及历史均保留 |
| 家长已注册才绑定 | 导入确认前核验本校有效 PARENT 账号的手机号；成功后同一事务建立绑定；不自动注册家长 |
| 家长解绑 | 档案详情提供绑定/解绑；解绑只改变绑定记录，保留学生与成绩历史 |
| 毕业只停用归档 | 学生列表「毕业归档」同时停用登录账号、归档学生；不删除档案、成绩、错题、会话和报告 |
| 任何错误阻止整批写入 | 预校验不创建账号/档案；确认时再次检查；事务失败回滚整个批次；允许的部分排除仅为管理员明确放弃的疑似重复教师 |
| 操作日志与结果汇总 | 预校验、导入、删除、离职/停用、毕业、家长绑定/解绑记录审计日志；回执保存成功/放弃行数、绑定数、操作人、时间及未匹配任教参考 |

## 模板与字段解释

三个下载附件从原 HTML 的 base64 内容直接提取，存放在 `apps/api/app/resources/roster/`，没有重新构造下载模板。教师模板 24 列 / 4 条样例，学生模板 30 列 / 49 条样例，错误清单模板 8 列 / 7 条样例。管理员应把样例替换为本批次资料后上传。

教师任课字段的「科目:年级.班级」与教研组长字段的「年级.科目」使用不同解析规则。班主任按指定班级授权，备课/教研组长按年级与学科授权，年级长按年级授权。校长、教务主任、总务主任在现有产品能力范围内生成学校数据查看角色，不因导入自动授予档案写入或跨校权限。运营维护沿用本校 `SCHOOL_ADMIN` / `SUPER_ADMIN` 写权限，QA 和学校查看角色只读；普通教师继续限定在任教范围。

原学生 30 列模板没有家长手机号字段。因此保留固定列结构，在导入预览里按 Excel 行号与学生账号补充可选家长手机号；不把学生「手机号」当作家长手机号。已注册家长通过 `users.phone`（兼容手机号作为登录名）与 PARENT 角色匹配。也可在档案详情补绑/解绑。此绑定不替代原有的报告分享授权流程。

流程图没有指定学生初始密码策略；实现采用与教师一致的「初始密码等于账号、首次登录改密」，确保新增学生账号可用。此前 CSV/旧系统同步的无登录账号档案保留「绑定现有学生账号」兼容入口，新的师生 Excel 导入自动建号。

上传边界：教师 `.xlsx`，学生 `.xls` / `.xlsx`，5 MB、最多 5000 行；文件读取只处理首个工作表，与原附件一致。学生大批量建号采用最多 8 路并行密码哈希计算，保持原 bcrypt 强度和整批事务。错误导出将所有单元格写为文本，避免把上传内容当作 Excel 公式。必填身份字段遵守现有账号系统的 100 字长度限制；单元格上限 5000 字。

## 代码与数据迁移

- `app/services/roster_excel.py`：模板列契约、解析、错误清单、角色与班级编码解析。
- `app/services/roster_workbench.py`：校验、疑似重复、原子导入、筛选、关联检查、毕业与绑定。
- `app/api/v1/endpoints/roster.py`：限定当前学校的档案 API。
- `app/db/models/roster.py`：教师资料、删除快照、导入批次、家长绑定。
- `alembic/versions/016_teacher_deletion_snapshots.py`：新增教师删除快照表；已有删除记录时拒绝降级，避免丢失追溯资料。
- `app/api/v1/endpoints/auth.py` / `app/api/deps.py`：账号密码自动识别身份、初始密码限制、改密与令牌失效。只有同一账号及密码匹配多个有效身份时，凭据验证后返回身份卡片；用户不需要输入学校 ID。
- `src/features/education/RosterWorkbench.tsx` / `src/pages/ChangePassword.tsx`：四条流程的操作页面。
- `alembic/versions/015_roster_workflows.py`：新增数据结构；登录名唯一键改为「学校 + 账号类型 + 登录名」，迁移现有账号类型，不改现有密码；学生学号不再作为唯一身份约束。

发布前安装 openpyxl 和 xlrd 依赖，并在目标数据库执行：

```bash
cd apps/api
python -m pip install -r requirements.txt
alembic upgrade head
```

测试与迁移演练在独立 QA 数据库中执行。当前运行中的业务容器和业务数据库未执行本次发布。若回退到 014，已有跨类型同名账号或重复非空学号会使旧唯一约束无法恢复；回退会明确失败，不会自动改写或删除人员身份。
