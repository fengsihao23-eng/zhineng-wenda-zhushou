## 1. 目标与交付层级

目标不是“看上去像旧系统”，而是使旧系统的重要任务在新系统中可找到、可执行、可验证，同时保留新系统的真实数据问答与治理底座。

| 层级 | 用户能得到什么 | 不能宣称什么 |
|---|---|---|
| A：可信接入 | 新系统可查旧考试、题目、报告；来源可打开；关键权限一致 | 不能宣称旧后台已可停用 |
| B：核心业务对齐 | 管理员可导入/维护必要数据；题库/试卷工作流、教师分析、学生复习、人工回复形成闭环 | 未迁移的旧域仍需保留，不能把高级推荐、自动批阅列为已完成 |
| C：受控升级 | 审核知识检索、家长门户、配置评测、运营质量与有限推荐 | 不等于通过市级容量、安全、灾备和法务验收 |

推荐按 A → B → C 发布，每一档都有单独门禁。核心对齐不以整库切换为前提；停用旧系统必须逐域决策。

## 2. 前置假设与待确认决策

### 2.1 估算前提

- 基于 2 名后端、1–2 名前端、1 名测试，产品/设计/数据负责人及运维安全按需参与。负责人栏为角色建议，未假设现实中已有这些人员。
- 旧系统可在隔离环境复验，且至少能提供受控导出或只读 API；不假设归档源码直接启动就可用。
- 学校数据、试卷、题库和报告的使用授权明确；迁移样本脱敏，测试不写入业务库。
- 后续所有工作继续保留现有工作区改动；不能靠恢复旧备份覆盖当前工程。
- 下表“人日”是实现、联调和专项回归的粗估投入，不等于连续工期，可能与共用组件复用重叠。试点观察、外部协调、数据清洗和采购等待另算。

### 2.2 G0 必须确认的事项

| 决策 | 建议默认值 | 确认方 | 不确认的影响 |
|---|---|---|---|
| 对齐基线 | 以旧实际实现为准，mock/空实现排除；冻结一版截图、接口与样本 | 产品 + 技术 + 业务代表 | 无法计算真实覆盖度和明确验收范围 |
| 品牌与视觉 | 保留“知行”识别，管理页回归清晰紧凑的工作台；不强制像素级复刻旧蓝色 | 产品 + 设计 | 易重复返工；未确认前只做布局与组件中性化 |
| 诊断权益 | 沿用明确 BASIC/DIAGNOSIS 边界直到业务批准变更；所有入口一致 | 业务 + 产品 + 法务/隐私负责人 | 阻塞诊断扩大开放，不阻塞一般成绩查询 |
| 教师/校长范围 | 教师任教班级/学科；校长学校汇总；个体查看单独授权 | 学校数据负责人 + 安全负责人 | 不开放全校学生明细给一般教师 |
| 分域写主 | 旧题库/试卷先保持写主，新会话/工单在新系统；其他域逐个切换 | 技术 + 数据负责人 | 不进行无补偿方案的跨库双写 |
| 首批上线承诺 | 先 A，再 B；C 中课程知识问答未就绪时明确关闭入口 | 产品 + 试点负责人 | 不把“有知识文档页面”宣传为知识问答已可用 |

这些决策是执行门禁，不是要求本次分析中断等待；可由项目启动会集中签认。

```text
  └─ B01 身份/ID映射与只读接入                        │
       ├─ B02 导入工作台 ─→ B03 基础数据与考务        │
       ├─ B04 试卷附件 ─→ B05 题库 ─→ B07 拆题/OCR  │
       │                    └─ B06 标签/知识点       │
       │                          ├─ C02 错题复习     │
       │                          └─ C03 教师分析     │
       └─ C01 正式报告 ───────────→ C04 问答证据     │
  A03 交互/状态修复 ─→ C05 人工回复与运营             │
                                                    ↓
                               Q01 回归与逐域切换 → B档验收
```

设计、权限、旧接口核验可并行；不得在题目/报告实体和映射未稳定前，先做无法落地的“加入复盘”“原始依据”按钮。

## 5. 第一轮迭代可直接开工的顺序

目标：用一轮迭代先解决“可信”和“接得上”，不承诺一轮内补齐题库/OCR。

| 顺序 | 可立即开始的工作 | 输出 / 完成判断 |
|---|---|---|
| 第 1–2 天 | A00；并行盘点旧环境/接口与需求冲突 | G0 签认表、角色能力矩阵、实体映射初稿、真实/演示功能清单 |
| 第 2–4 天 | A01 的 Prompt/诊断/关联范围；A03 的虚入口与状态流；D01 样例 | 负向权限用例、明确禁用态/说明、风险与知识返工路径、三类页面样例 |
| 第 3–6 天 | B01 受控样本对账；B02 导入 API 契约与 UI 框架；A02 共享撤销设计 | 可预检的脱敏样本、字段错误规范、任务状态协议、跨进程撤销测试 |
| 第 5–8 天 | 打通一份最小成绩批次→账号绑定→学生查询；D02 数据口径复用 | 真实导入后可登录查分，失败/重复/跨校样本回归通过 |
| 第 9–10 天 | Q01 联合检查；确认 M1 与题库只读接入排期 | M0 未通过项不得带到生产；明确本轮完成、未完成和剩余估算 |

这一顺序是并行开工示例，不保证所有大任务在十天内全部完成。任教范围关系改造、旧数据清洗等若超出预估，应缩小开放范围并报告，不以放宽权限换工期。

## 6. 关键技术/产品契约（实施前需补成正式规范）

### 6.1 新旧实体映射

| 旧业务实体 | 当前新系统承接点 | 仍须补充的内容 |
|---|---|---|
| 学校、用户、学生 | schools/users/students 与当前鉴权 | 来源实体 ID、账号绑定冲突、组织范围；禁止按姓名自动合并 |
| 教师、班级、任教关系 | ImportedClass/外部班级信息，角色体系 | 任教关系和生效期、班级归属；ImportedClass 不等于完整教学权限模型 |
| 考试、科目、成绩 | exams/subjects/成绩三类表 | 来源版本/批次/时间、考试科目关系校验、满分与排名口径、导入后可追溯 |
| 试卷文件、页、框选区域、草稿 | 暂无完整对应领域 | 原件与版本、页码与坐标、草稿状态、发布批次、异步任务与对象存储；名称需架构评审 |
| 材料、大题、小题、独立题 | question_scores 中只有 question_id | 正式题库/版本/层级与来源、映射表、题库与小题成绩的真实关联 |
| 知识点与标签 | question_scores.knowledge_point_id | 知识点树、题目多对多、字典版本、删除/合并影响范围 |
| 学情/批阅报告 | diagnosis_reports | 分类映射、原件/版本、正式状态、结构化字段契约；不能把任何 PDF 当成诊断 JSON |
| 诊断权益 | student_entitlements | 来源、范围、有效期、撤销与同步；导入成绩不自动赋予权益 |
| 人工对话 | human_handoffs 为任务载体 | 会话/消息/附件/可见范围/回复记录，历史是否迁移取决于授权与保留期限 |
| 模型/Prompt 配置 | Gateway、PromptRegistry | 作用域映射、凭据安全重配；不导出或复制旧明文密钥 |

以上新增项为设计任务，不暗示它们已在代码中存在。字段及表名在 B01 冻结，并以实际旧表结构为准。

### 6.2 建议接口边界

下面是**建议新增契约**，不是当前可调用接口清单：

- 导入域：创建批次、上传文件、字段映射/预检、读取错误报告、确认执行、查询进度/回执。首版异步任务不等于 HTTP 请求长期悬挂；明确幂等键、学校范围、创建者和批次 hash。
- 教务域：学校授权范围内基础数据和考试科目管理；先只读暴露旧来源，再按域切写；查询分页/筛选必须在服务端完成。
- 题库域：列表、版本详情、草稿、发布、引用检查、软删除/恢复；图片/解析/知识点应绑定同一版本。
- 拆题域：原件页、区域/草稿增量保存、OCR 任务启动/重试/进度、差异预览与发布；发布使用幂等键，不将重复点击变成重复题。
- 证据域：通过受权证据 ID 打开考试、原题或报告版本；历史 sources 持久化，删除/失效后返回明确状态而不是静默消失。
- 人工域：工单详情、受权上下文、消息、回复、状态迁移与通知回执；每条消息关联发送者角色、时间及可见范围。

所有写接口统一错误码、请求 ID、审计事件与重复提交策略。知识文档审核、题库发布和 Prompt 发布必须分别建状态机，不能复用一个任意字符串状态更新接口。

### 6.3 安全输出与流式决策

现有实现是完成整轮后经 SSE 发送全部答案。C04 必须从下列策略中明确选择并记录：

1. 首版保留审核后输出，真实展示“查询中/生成中/校验中”等事件，校验完成再返回答案；不得标为真实逐字生成。
2. 只有完成增量内容安全方案后，才接 Gateway 增量输出；未校验文本如何处理、取消后成本/持久化如何收尾、被拦截内容是否已泄露，均纳入验收。

优先推荐策略 1 支撑核心迁移；不要为“打字效果”先把未校验的未成年人内容直接展示。是否升级策略 2 是产品/安全联合决策，而非单纯前端动画任务。

## 7. 验收用例与发布门禁

### 7.1 必跑场景

使用至少两所隔离测试学校、不同任教班级、BASIC/DIAGNOSIS 用户、多个考试、无/有报告、有效/过期授权、已发布/草稿/被引用题目等脱敏夹具。下表是新增验收要求，不是本轮测试结果。

| 编号 | 验收场景 | 通过标准 |
|---|---|---|
| AC-01 | 跨角色、跨学生、跨班级、跨学校、跨组织请求 | 未授权数据与计数均不可读；管理写入拒绝；前后端结果一致；无“只隐藏菜单”情况 |
| AC-02 | 诊断报告三入口与 Prompt 作用域 | 页面、工具、原件统一权益；学校角色无法发布全局模板；授权有效期/撤销立即按约定生效 |
| AC-03 | 登出、刷新重放、服务重启、多 worker | 撤销凭据在所有进程失效；生产不渲染测试凭据；日志和文件 URL 不含访问 Token |
| AC-04 | 成绩导入成功/错误/重复/冲突 | 同批同 hash 幂等；失败批次不污染业务数据；错误定位到文件/行/字段；导入后同账号真实可查询 |
| AC-05 | 新旧快照对账 | 相同范围/时间，人数、考试数、题数、分数/满分/排名按冻结口径一致；每项差异有原因与批准，不用总数一致掩盖错人 |
| AC-06 | 原件上传→拆题→编辑→刷新→发布 | 草稿和区域不丢；跨页、长图和缩放可用；只发布人工确认版本；重复确认不产生重复题；失败可恢复 |
| AC-07 | 引用题删除/混合批量操作/恢复 | 被引用题有明确阻断原因和影响范围；逐项回执；允许项按约定处理；恢复不破坏已发布报告与成绩关联 |
| AC-08 | 错题→订正→复习 | 正确题目/版本/得分可定位；订正与复习记录持久化；刷新、多端重新登录可回读；失分事实与掌握判断分开 |
| AC-09 | 教师班级汇总→学生详情 | 仅任教范围，样本量可见；聚合能与原始成绩对账；查看个体留痕；无数据/缺知识点明确提示 |
| AC-10 | 问答→依据→反馈→刷新/重试/停止 | 考试/学科参数真实生效；来源可打开且历史保留；单消息反馈进入队列；相同消息 ID 不重复写；状态与输出策略一致 |
| AC-11 | 求助→接单→回复→学生查看→关闭/重开 | 双向消息真实落库；学生看到真实跟进人/状态/回复；越权看不到上下文；重开/关闭有记录 |
| AC-12 | 风险/反馈/知识文档状态流 | 风险确认后可解决；拒绝非法状态；知识驳回后可修改再提交；处理说明不是固定假文案；操作可审计 |
| AC-13 | 桌面/移动/键盘/中文输入 | 320/390/768/1440px 无内容裁切或不可达操作；焦点可见；状态不只靠颜色；中文输入法回车不误发送；保持已有图表回归 |
| AC-14 | 知识检索与内容下线（U01 开放门禁） | 仅审核且许可资料可检索；来源精确到版本/片段；草稿、过期、跨校被排除；下线传播时间按约定实测；证据不足明确拒答 |
| AC-15 | 真实模型/配置发布/异常回退 | 合同假数据与真实 Provider 回归分开；覆盖数值、指定考试、缺数据、越权诱导、高风险内容；不出现阻断级危险建议或越权；新版本评测过门禁再发布 |

### 7.2 完成定义

每项功能必须附：

1. 指定角色可找到的入口和正常完成路径。
2. 实际数据来源、字段/时间/版本与持久化回读。
3. 后端权限和跨范围负向测试。
4. 加载、空值、无权限、失败、超时、取消、重复提交等状态。
5. API/契约/端到端证据，以及业务验收人。
6. 可回退方式与对旧系统的影响说明。

现有 QA 记录中的 66 项后端、8 项前端单测和 70 项 Chromium 用例是值得保留的历史基线；它们不证明新增题库/教务管理工作流，也不证明真实模型质量。本次没有重跑这些测试。

### 7.3 覆盖度如何量化

- 以冻结后的 F01–F26 和旅程为分母，而不是页面/接口数量。
- 每项记录“不迁移（有批准理由）/待核/未做/只读接入/可操作未闭环/闭环验收”。
- B 档通过率＝已闭环验收的 B 档必选项 ÷ 已批准的 B 档必选项；另列 P0 未关闭数、未决数据差异数和遗留权限风险，不互相抵消。
- 旧 mock 排除出“既有成熟能力”分母，但若是目标业务仍可作为新增需求列入；不得用剔除必要业务来提高比例。
- 首次发布要求：相应范围 P0 为 0、必选旅程通过、权限负向用例全通过、迁移关键字段无未解释差异；P1 豁免必须有负责人/期限/缩小的开放范围。

## 8. 灰度、对账与回退

| 阶段 | 操作原则 | 回退触发 / 动作 |
|---|---|---|
| 只读影子 | 新系统读取受控快照/Adapter；旧域继续写；仅测试学校使用 | 发现错人/跨校/版本错配立即停用该域入口，保留旧入口；修映射后重新对账 |
| 少量学校灰度 | 按学校/角色/业务域功能开关开放；记录每个域写主与数据水位 | 导入污染、证据打不开或核心旅程阻断时关闭相应能力，不连带停所有聊天 |
| 单域写主切换 | 预检、备份、冻结写入窗口、增量补齐、对账后切流 | 恢复旧入口前明确处理新域已产生的有效写入；先暂停写，导出/补偿，不丢弃新数据 |
| 稳定观察 | 7–14 天观察业务成功率、错误/转接、数据差异、人工负担 | 指标阈值在试点前签认；超限暂停扩校，复验后继续 |
| 旧域退役 | 业务负责人确认无依赖后改只读归档，保留法定/约定期限 | 未验证恢复演练、附件与引用完整性前不删除旧库/原件 |

回退不能通过重置整个仓库、清空业务库或覆盖用户已有改动实现。任务日志/批次号/来源映射/证据版本在回退后仍保留以供审计。

## 9. 关键风险与应对

| 风险 | 预警信号 | 应对 |
|---|---|---|
| 旧源码/部署/备份版本不一致 | 同一路由存在多个实现或依赖缺失 | G0 固定运行版本与 hash；归档截图只作参考；先最小隔离复验 |
| 产品名相同而实体不同 | 把知识文档当题库，把 JSON 诊断当所有报告 | 分领域模型与验收；明确 F07/F12/F22 的边界 |
| 迁移只有总量一致 | 成绩或原件归错学生/考试 | 关键外部 ID 与复合归属校验；实体级抽样 + 全量关联检查 |
| 把安全能力视为已完成 | 有 Guard/风险表即认为高风险可控 | 真实内容评测、事件闭环、应急策略单独过门禁 |
| 用户看到菜单但办不完事 | 虚按钮、无详情、状态不可继续 | 每张任务卡必须挂 J/AC，发布前做角色旅程验收 |
| 两套题库长期分叉 | 相似题读新题库、成绩仍连旧题目 | 单一领域契约与来源映射；迁移期保留兼容层，不永久复制导航 |
| 三种设计系统并存 | 旧蓝色、DESIGN.md 黑白、实际紫色各自扩散 | D01 冻结品牌与组件；先典型页面验证再推广 |
| 大范围重写拖慢交付 | 一期同时重建 OCR、RAG、推荐、身份、题库 | A/B/C 分档、只读优先、分域切换；U05 明确后置 |
