# 新旧系统对齐：数据契约与运行说明

日期：2026-09-18。此说明对应当前工作区的增量实现，以新系统为业务主线。没有连接旧业务数据库、遍历旧数据文件、读取 `.env` 或导入真实学生数据。

## 1. 写入边界与实体字典

- 新会话、人工消息、复习记录、原生题库/试卷由新系统写入。
- 旧资料通过学校管理员明确提交的受控 JSON 快照投影到新系统；不向旧系统回写。页面显示 `controlled_snapshot`、来源版本和水位，不能称为实时同步。
- 旧整数 ID 保持字符串。映射唯一键为 `(school_id, source_system, entity_type, external_id, source_version)`。不同学校、来源、实体类型不会因为 ID 相同而串号。
- 同一个来源实体的新版本复用稳定的新实体 ID；报告每个正式版本有独立 ID，以沿用报告级权益。来源版本相同且哈希相同则返回原回执；同版本不同内容 409。来源水位不能倒退。
- 原生与外部记录分开写入。外部题目、试卷不允许通过原生编辑接口修改。教师账号维护沿用已有身份体系，不创建默认密码或为导入档案自动授予角色。

| 业务对象 | 新系统实体 | 核心关系/单位 |
|---|---|---|
| 学校、师生、班级 | 原 `schools/users/students/import_classes` | 当前学校来自数据库认证结果；学生以外部 ID/学号绑定，不按姓名合并；新增班级状态 |
| 教师任教 | 原 `teaching_assignments` | 教师—班级—学科、有效期；复用 M0 授权，不授予全校任意明细 |
| 考试、学科、成绩 | 原 `exams/subjects/exam_subjects/*scores` | 分数为十进制数、排名为正整数；满分未知仍为未知；不交给模型计算 |
| 来源 | `education_sources` | 来源系统、旧 ID、实体类型、新 ID、来源版本、SHA-256、带时区水位、不可变来源字段 |
| 导入工作区 | `education_imports` | 文件内容、映射、修订号、状态、事务回执；原 `data_import_batches/rows` 继续保留 staging |
| 映射模板 | `education_mapping_templates` | 同校名称+版本唯一；保存总是新增版本 |
| 私有附件 | `education_assets` | 不可变内容、实际 MIME、大小、页信息、SHA-256、存储键；首版存于数据库私有二进制字段 |
| 试卷 | `education_papers/education_paper_versions` | 试卷→考试+学科；原件替换新增版本，旧版本不覆盖 |
| 题库 | `education_questions/education_question_versions` | 材料→大题→小题；大题可独立为根；独立题无父级。正文、选项、答案、解析、原件版本、区域和标签属于版本 |
| 知识点/标签 | `education_taxonomy/education_question_tags` | 同学科、同字典类型父子树；版本化题目与标签多对多；删除/恢复有引用检查 |
| 拆题 | `education_paper_drafts/education_ocr_jobs` | 原件版本→草稿修订→区域/OCR 结果→人工确认→正式题目 ID 回执 |
| 报告 | 原 `diagnosis_reports` + `education_report_attachments` | 每份正式报告的版本与原件固定；报告原件不能复用于试卷或另一个报告 |
| 复习 | `education_reviews/education_review_records` | 本人小题得分记录→正式题目版本；每次订正独立追加，掌握状态明确为学生自评 |
| 人工服务 | 原 `human_handoffs` + `education_handoff_messages` | 工单归属和 M0 状态机保留；双方消息、处理人、真实处理说明可回读 |
| 问答依据 | `chat_messages.sources/selected_context` | 固化回答时的事实与来源版本；打开依据时重新校验本人范围/报告权益 |

## 2. 只读旧资料接入契约

管理入口：`/admin/sources`。API：`POST /api/v1/platform/education/legacy-snapshots`。原始旧代码只用于核对考试日期/科目、报告类型/原件、题库父子和人工会话的业务语义，没有复制旧实现。

```json
{
  "source_system": "legacy_export",
  "source_version": "v1",
  "captured_at": "2026-09-18T00:00:00Z",
  "records": [
    {"entity_type": "exam", "external_id": "old-exam-1", "name": "合成考试", "exam_type": "monthly", "start_date": "2026-09-01"}
  ]
}
```

完整可执行字段定义见 `apps/api/app/schemas/legacy_snapshot.py` 和 OpenAPI。支持 `exam/paper/question/report/score` 五类；依赖按考试→试卷→父题在前的题目→报告→成绩处理。整批失败回滚，不保留已写入的前半批。

| 旧业务语义 | 受控导出字段 | 校验/投影 |
|---|---|---|
| 旧考试 ID、考试日期 | `external_id`、`start_date` | 旧 `exam_date` 由导出方规范为 ISO 日期；新考试 ID 由服务端生成 |
| 考试科目 | `subject_id` | 必须显式选用本校新学科 UUID；不靠名称猜测学科 |
| 学生身份 | `student_external_id` | 必须匹配已建立的本校学生外部身份；缺映射拒绝，不创建不明学生 |
| 旧试卷 ID、原件 | `external_id`、`exam_external_id`、`asset_id` | 原件先经受权上传及类型校验；`asset_id` 不能是路径或外部 URL |
| 材料、大题、小题 | `kind`、`parent_external_id` | 父题须先提供，父子同学科，独立题不能冒用父级 |
| 题干/选项/答案/解析 | `stem/options/answer/explanation` | 每个导出版本生成不可变正文版本；学生得分绑定明确版本 |
| 成绩/小题得分 | `score/full_score/question_no/question_external_id` | 总分不填学科；学科分填学科；小题还需题目与题号。丢分由代码计算 |
| 诊断/成绩/批阅报告 | `report_type/raw_content/summary/asset_id/generated_at` | 分别标注 `diagnosis/score_report/marked_work`，没有自动批改；缺原件明确显示未接入 |

旧系统可用性、实际导出和真实数据对账仍需学校数据负责人提供已批准的脱敏样本。当前完成的是接收和对账机制的合成验证，不是实际迁移对账签认。

## 3. 成绩导入

入口 `/admin/imports`；首版支持 UTF-8/UTF-8 BOM CSV，八个固定文件：

- `schools.csv`：`external_school_id,name,code`。
- `classes.csv`：`external_class_id,school_code,name`。
- `students.csv`：`external_student_id,school_code,student_no,name`，可选 `external_class_id`。
- `exams.csv`：`external_exam_id,school_code,name,exam_type`，可选开始/结束日期、学年、学期。
- `subjects.csv`：`external_subject_id,school_code,code,name`。
- `student_exam_scores.csv`：学生、考试、学校外部标识和 `total_score`，可选满分/排名/人数。
- `student_subject_scores.csv`：学生、考试、学科、学校外部标识、`score,full_score`。
- `question_scores.csv`：学生、考试、学科、学校外部标识、`question_no,score,full_score,lost_score`；可选正式 `question_version_id`。

每批最多 5 MB、5000 行，恰好一所当前学校。页面映射目标字段到原始列，预检返回文件、行号、字段说明和稳定错误码。校验包括引用、身份冲突、有限数值、得分/满分/丢分关系及同考试科目满分一致性。已固定的小题版本不可由导入静默覆盖。

状态：`uploaded → ready/invalid → running → succeeded/failed`。修改映射必须提供当前修订号；确认冻结预检内容。复用原 `CsvImportService` 的事务写入与 staging，不再实现另一套成绩写入器。失败后业务表和来源映射一起回滚。进度只显示真实阶段：事务提交前不伪造逐行完成百分比，提交后 100%。回执单列未绑定账号数。

同学校同批次号、同上传内容返回同一个工作区；同编号不同内容 409。确认/重试不重复插入已成功的批次。映射模板新增版本；账号绑定必须在师生工作台单独确认。

## 4. 原件、拆题和 OCR

- 文件首版限定有效 PDF/PNG/JPEG，15 MB、100 页；校验扩展名、文件签名、实际解码、图片像素上限和页尺寸。拒绝路径穿越文件名和任意远程 URL。
- 文件没有公开静态 URL。`GET /platform/education/assets/{id}` 每次认证、校验学校/任教/学生考试或报告权益，并记录读取审计。响应 `no-store/nosniff`；浏览器通过受权请求获取临时 Blob，不在 URL 中拼 Token。
- 私有原件目前在 PostgreSQL 二进制字段中，`storage_key` 是稳定迁移键。**没有宣称对象存储接入已交付**；达到较大文件量前需迁移到经同样权限校验的对象存储。
- 页坐标为 `[0,1]` 归一化的 `x/y/width/height`，包含页码，允许同题跨页多个区域。支持鼠标框选、缩放和键盘输入坐标。手机只读，避免不可用的窄屏编辑承诺。
- 草稿编辑约 1.2 秒防抖保存，显示未保存/保存中/已保存；修订号 CAS 防止覆盖其他人的编辑。刷新从服务端恢复。浏览器离开时提醒尚未保存的修改。
- OCR 任务真实调用本地 Tesseract，要求 `chi_sim` 与 `eng`。结果单独保存，显示差异，由操作者选择应用到草稿；不会自动覆盖人工内容。
- 失败码包括引擎未安装、语言缺失、超时、执行失败、输入失败。同草稿修订最多重试五次；已变更草稿不能直接套用过期结果。
- 人工确认时核对当前修订，所有题干非空才可发布。发布回执固定新题 ID，重复确认不重复建题。已发布拆题草稿冻结；后续编辑产生新的题目或原件版本。
- 已实现本地 OCR 与人工结构化流程；未实现生成式 AI 自动拆题、手写数学公式识别保证、覆盖式发布/跨系统写主切换。

API 内提供确认后的后台执行；持久任务可由 `apps/api/scripts/education_worker.py --once` 补偿一个有限批次，或不带 `--once` 交由进程管理器常驻。Worker 只处理已授权确认的任务，使用学校锁与任务行锁，支持进程中断后再次领取。生产部署需显式运行 Worker；本轮没有修改或重启业务 Compose 服务。

API Dockerfile 已声明 Tesseract 与中英文语言包，Python 依赖包含 Pillow 和 PDFium。Docker 镜像尚未在业务环境重建。开发机本轮安装的 Tesseract 和简体中文模型仅用于合成验收。

## 5. 权限与回读

| 能力 | 学生 | 教师 | 学校管理员 | QA |
|---|---|---|---|---|
| 教务、导入、来源映射 | 拒绝 | 只读任教所需选项；无导入/来源 | 本校读写 | 本校只读 |
| 题库、试卷 | 本人考试关联的正式依据/原件 | 本校任教学科正式题目；试卷还校验任教班级考试 | 本校读写 | 本校只读 |
| 班级分析 | 拒绝 | 当前有效任教班级+学科 | 本校 | 本校只读 |
| 报告原件 | 本人且正式且当前有效权益 | 无报告管理/原件权限 | 本校 | 本校只读 |
| 复习记录 | 本人读写 | 不通过学生接口读取 | 不通过学生接口读取 | 不通过学生接口读取 |
| 工单消息 | 本人工单补充/确认/带原因重开 | 任教学生工单，接单人可回复 | 本校处理与回复 | 读取，不能回复 |

全局超级管理员可进入其当前学校的新增教务能力；一般市级运营角色没有因此获得教务写权限。沿用已有市级汇总，不扩大跨校学生明细开放。

问答考试和学科范围在会话保存；发送中的范围不能修改。确定性 Tool 使用选定考试/学科，趋势以所选考试为截止范围。历史消息和重复请求返回已保存的 `sources`。依据卡显示回答生成时固化的分数/报告版本；打开时重新校验身份与权益，授权撤销后拒绝。输出仍为 Guard 审核后整段发送，不称为真实逐 Token 生成。安全 Markdown/公式禁用原始 HTML、外部图片和模型生成的链接导航。

## 6. 迁移和运行

新增迁移 `014_education_workbench`，下接已有 `013_operation_receipts`。增加 16 张域表、原件和正文版本关联、消息来源/上下文列、班级状态，以及学生账号唯一绑定索引。

- 本轮仅在新建 `qa-education-20260918` 容器的 `qa_education`/`qa_education_unit` 隔离库运行迁移和合成测试。
- 正式应用迁移前先审查现存重复账号绑定和旧会话考试归属。迁移会因不合法数据失败，不自动改归属或删除冲突记录。
- 迁移文件使用冻结 DDL，没有在迁移执行时导入新的业务 ORM 定义来隐式改表。
- 一旦写入题目/原件/复习数据，回退应停用新入口、保留新增表和记录；不能直接 downgrade 删除新业务记录。
- 未执行真实迁移、旧域停用、生产发布、外部凭据配置或破坏性业务库操作。

可重复的浏览器运行器：`node tests/education/run.mjs`。它要求上述一次性 QA 库已迁移，强制使用 Fake Model Provider 和合成身份，在临时目录运行 API 与生产 Web 构建；Vite 的 `envDir` 指向空临时目录，避免读取项目 `.env`，也不覆盖现有 `apps/web/dist`。测试凭据运行时生成、不写入报告，关闭浏览器 trace/video。
