# 教师档案 r79 / 原型 v3 对齐

依据用户提供的 `业务流程图_V1.html`（2026-10-10、r79）中两个子流程：**教师批量导入（新增）**、**教师删除 / 信息变更**；页面交互按 `教师档案页_高保真原型.html`（v3）实现。

入口：学校管理台 → 师生班级与考试 → 教师档案，路径 `/admin/school?tab=teachers`。

## 页面与业务行为

| 原型 / 规则 | 实现 |
| --- | --- |
| 教师信息列表 | 姓名与登录账号、原表任课班级、脱敏手机号与职务、查看档案 / 删除；关键词同时检索姓名、账号和原手机号 |
| 批量删除 | 勾选当前页，筛选或翻页清空选择；逐条展开核对 24 列原档案，必选原因并二次确认 |
| 删除原因 | 离职、停用、错导入纠错、变更前删除、其他；「其他」必须填写说明 |
| 纯删除 | 停止登录、立即释放账号，长期保留原 ID、24 列快照、删除人、原因、时间与历史外键；不建立任务，不关联未来新增或复职 |
| 资料变更 | 「变更前删除」建立绑定所选原教师 ID 的专属任务；取消或失败保留任务，旧档案不自动恢复 |
| 三步新增向导 | 上传 → 预校验与错误清单 → 疑似重复逐条确认及回执；任一错误整批退回 |
| 教师账号 | 姓名、账号必填；账号须为完整 11 位手机号，同校教师及同文件内唯一；学生 / 家长同名账号不拦截 |
| 手机号码 | 可为空、包含 `*` 等脱敏字符或不同于登录账号，按原值保存；完整 11 位手机号校验仅适用于「教师账号」（2026-10-13 按经理反馈修正） |
| 疑似重复 | 姓名及任课年级班级整格文本完全一致；任课为空者不比对。新增默认保留、逐条核对后可保留 / 放弃；变更仅提醒，不允许单行放弃 |
| 任课与角色 | 任课不做字典匹配拦截。任课、班主任、教研组长、年级长、校领导结构化字段生成角色并取并集；「说明」不产生角色或管理权限 |
| 变更文件 | 按原型使用 **25 列＝24 列模板＋教师ID**。下载时锁定教师ID；后台校验完整列名、列序、人数及教师ID集合 |
| 新旧对应 | 单人单行自动关联；批量逐行指定原教师，须与锁定教师ID一致、覆盖所有原教师、无重复关联，并显式核实身份 |
| 提交 | 展示原教师ID、Excel行号与变更前后值，勾选核对后整批原子提交；提交前再次校验账号和疑似重复 |
| 成功变更 | 沿用原用户 / 教师ID，历史外键保留；原 24 列快照与更新后 24 列资料均可查；最新角色与任教范围重建，原任教关系保留历史记录 |
| 密码 | 新增和变更均将初始密码设为新教师账号并强制首登修改；删除及变更使旧令牌失效 |
| 操作记录抽屉 | 导入回执、删除快照（含变更任务）；按姓名 / 账号 / 批次 / 任务 / 文件检索，按删除原因筛选；支持继续任务、查看回执及版本对照 |
| 原文件 | 新批次保存并下载真实上传字节；迁移前未保存的原文件不会伪造，仍可查看原始资料明细 |

流程图文字提到 24 列变更模板、任务保存教师ID；原型明确细化为追加锁定教师ID的 25 列文件。本次按用户要求的原型执行，新增模板仍为原 24 列。

## 迁移与兼容

数据库迁移 `018_teacher_change_tasks` 新增专属任务、删除原因与批次、版本资料、原文件存储，并移除「每个教师仅允许一个删除快照」的旧限制，支持同一稳定 ID 多次变更。

从 GitHub 全新部署时，若没有私有教师样例工作簿，下载接口会生成空白 24 列教师模板。服务器已有样例工作簿时可直接读取；模板结构一致，部署不依赖发布真实教师文件。

历史删除快照标记为 `legacy`，保留原字段与旧关联；不根据相同账号推断新的变更任务。旧教师导入、批次、历史和删除记录 URL 会跳转到新页面对应入口。普通导入不能消费删除快照；旧无原因教师删除 / 离职 / 停用 API 返回明确引导，必须改走有原因的删除接口。

部署更新时执行：

```bash
cd apps/api
alembic upgrade head
```

本次迁移演练与真实联动验收均使用独立的本地测试数据库。
