## 1. 结论：需要补回业务工作台，不是只换一套皮肤

旧系统的核心产品形态是“学校教务生产后台 + 多角色学习助手”；新系统的核心形态是“学生学情消费端 + 轻量运营治理台”。新系统已经有真实查询和持久化能力，并非只有聊天原型，但尚不能替代旧系统的教务生产流程。

建议目标是：**用新系统的身份、数据、问答与治理底座，承接旧系统的教务工作台和学习闭环；保留业务语义与操作习惯，升级权限、状态流、可追溯性和设计一致性。**

最重要的六个判断：

1. **最显著的覆盖缺口在上游。** 试卷管理、人工框选/OCR、题库、知识点标签、考务与成绩导入工作台，在新前端没有对应入口；不能用已有成绩表和“知识库治理”替代这些能力。
2. **部分同名功能深度下降。** 新“错题分析”是失分题清单，未形成题干—解析—订正—复习；新“人工转接”是工单状态，旧系统已有人工会话、消息与回复；新“诊断报告”主要是读取，不是报告生产和文件管理。
3. **新系统的底座值得保留。** 本人/学校范围查询、成绩复合归属约束、会话持久化与幂等、确定性学情工具、Prompt 版本、Trace、CSV 事务导入、身份隔离缓存、错误反馈和已修复的图表均有实质代码。
4. **已有底座不等于权限闭环。** 教师目前按学校而非任教班级过滤；学校管理员可以访问全局 Prompt 发布接口；诊断页面与工具权益规则不一致。这些应先于扩大功能开放处理。
5. **旧系统也不能全盘照搬。** 旧仪表盘、部分成绩分析、家长关联和知识点导入含演示数据；旧“新题库”存在隔离模块且未完整接入练习推荐。应迁移已证实业务能力，而不是复制“功能很多”的表象。
6. **对齐完成度要按真实旅程验收。** 页面可见、接口存在、历史测试通过，都不单独等于用户能办完一件事。此次不提供缺乏统一分母的“完成百分比”。

## 3. 产品形态与角色对齐

| 维度 | 旧系统 | 新系统 | 对齐建议 |
|---|---|---|---|
| 学校后台 | 基础数据、题库、考试、成绩、报告、试卷、权限、映射、模型/提示词、人工对话 | 学生列表、知识文档、反馈、风险、转接 | 恢复“业务生产”和“系统配置”分组；保留独立的治理分组 |
| 学生入口 | 学习助手中嵌成绩、错题、相似题、查询入口 | 学习总览、成绩概览、成绩趋势、诊断、错题、问答、支持 | 保留新角色空间；把三处重复成绩展示收敛为首页摘要 + 成绩中心 |
| 教师/校长 | 角色化助手、班级/全校分析入口；部分是快捷问题而非独立业务实现 | 教师总览与学生队列；校长无独立角色空间 | 优先建设授权班级分析；校长先按“校级汇总能力”设计，不默认拥有全部管理写权限 |
| 家长 | 角色配置、部分查询路径；家长关联界面存在 mock | 学生发起分享码授权，缺家长门户与身份消费闭环 | 保留授权意图；实名/监护关系、范围、期限、撤销通过前不开放成绩消费 |
| 市级运营 | 旧学校后台不能直接视为市级平台 | 有市级空间与跨学校统计 | 保留，并补组织范围和默认脱敏；不能把“看所有学校”视为完整市—区县体系 |
| QA/审计 | 历史测试与后台配置入口 | QA 被归为学校空间，Prompt/Trace 主要在接口层 | 增加按能力授权的配置/追踪入口，不把 QA 自动视为全局发布者 |

证据：L01、L02、N01、N07、N12、R01、R02。

## 5. 设计对齐：保留工作方式，升级视觉与交互

### 5.1 当前设计的主要偏差

| 维度 | 当前观察 | 目标方案（建议，不是已实现） |
|---|---|---|
| 信息架构 | 旧后台按基础数据/题库/考试/设置分组；新后台主要是治理队列 | 业务生产、教学分析、运营治理、系统设置四组；按权限显示，避免单级长菜单 |
| 管理页密度 | 新学生页的大标题、留白和卡片延续到后台，缺批量任务工具栏 | 管理端“标题 + 当前学校/考试范围 + 筛选 + 表格/详情 + 批量操作”；密集与舒适两档 |
| 学生页重复 | 首页、成绩概览、成绩趋势重复展示总分和科目；两套趋势图实现 | 首页突出“本次变化与下一步”；成绩中心承载考试/学科/趋势；同一查询和图表组件 |
| 字体 | 当前全局以衬线字体呈现中文业务界面 | 正文、表格、输入使用系统中文无衬线；数字等宽；品牌标题可保留少量衬线，不强制整体返旧 |
| 色彩 | 当前紫色品牌可识别，但大面积渐变抢占注意；危险操作也可能只是灰色 | 保留一个靛蓝品牌色，内容区白/中性浅底；红/橙/绿明确风险/待办/完成，配文字和图形 |
| 图标与状态 | Unicode、emoji 混用；不同状态用近似单色；头像下拉外观实际直接退出 | 单一图标体系；所有状态有文字；菜单真展开，退出为明确动作 |
| 工作台布局 | 旧拆题三栏体现“区域列表—原图—属性”；新系统暂无承接组件 | 保留三栏业务心智，升级原图缩放、选择同步、未保存提示、任务状态与可恢复草稿 |
| 移动端 | 已有窄屏修复，但 320px 下仍占 60px 固定侧栏 | 学生端抽屉或简明底部导航；教师/管理桌面优先；复杂拆题在手机明确提供只读模式 |
| 设计文档 | `DESIGN.md` 写奶油黑白、无渐变无阴影，实际 CSS 为淡紫+渐变 | 确认唯一设计基线并更新文档；不把不匹配的参考风格当强制规范 |
| 数据可信度 | 部分“已同步”“已生成”“可追溯”文字未对应完整状态或可打开证据 | 显示真实更新时间、范围、来源与状态；未知显示“待补充”，禁止用装饰文案冒充完成 |

建议组件基线：`WorkspaceShell`、`ScopePicker`、`PageToolbar`、`FilterBar`、`DataTable`、`DetailDrawer`、`StatusBadge`、`EvidenceCard`、`ImportWizard`、`TaskProgress`、`ConfirmDialog`。这些是后续组件建议名，不是当前仓库已有实现。

桌面管理页可从 240px 侧栏、56px 顶栏、40–48px 表格行高起步；学生页使用更舒适间距。具体数值需用真实长中文、表格和 320/390/768/1440px 样例验收，而非仅凭设计图批准。

### 5.2 建议的信息架构

```text
学生空间
├─ 学习首页：身份、数据时间、最近变化、下一步
├─ 成绩中心：考试 → 学科 → 小题 → 证据；趋势为页内标签
├─ 错题与复习：题目 → 解析/提示 → 订正 → 复习记录
├─ 学习报告：摘要 → 正式报告/原件 → 围绕报告提问
├─ 智能问答：场景入口、会话、引用、反馈
└─ 支持：人工消息与进度；家长授权作为独立子模块

学校/教师工作台（按能力授权，不是人人看到全部）
├─ 业务生产：师生班级、考务、成绩导入、试卷与拆题、题库/标签
├─ 教学分析：授权班级、学生详情、报告/批阅文件
├─ 运营治理：人工服务、反馈、风险、知识文档
└─ 系统设置：映射模板、Prompt、模型、运行追踪

市级运营中心
└─ 组织接入、脱敏质量/风险汇总、平台配置与应急停用
```

兼容现有 `/profile`、`/trends`、`/diagnosis` 等书签，逐步重定向到新信息架构；不要先删除页面再补能力。旧 `/admin/...` 与新同名前缀冲突，应通过明确的旧系统入口和路由映射处理，不能简单转发整个路径前缀。

## 6. 必须按旅程对齐的八条业务链

| 旅程 | 当前断点 | 完成定义 |
|---|---|---|
| J01 管理员导入成绩 → 学生查分 | 脚本可导入，学校人员无产品入口；账号绑定不在该导入流程内 | 映射/预检/错误修复/确认可完成；学生能登录查到同批次数据，重复导入不重复生成 |
| J02 试卷上传 → 拆题 → 正式题库 | 新系统缺整条生产链 | 原件与区域可回看；编辑刷新不丢；人工确认后才发布；失败可重试；引用题不误删 |
| J03 看成绩 → 找失分题 → 复盘 | 只有题号/分数，“加入复盘”无动作 | 看得到正确版本题干、解析及原始得分；可订正/记录复习；结果可回读 |
| J04 教师选班级/学生 → 分析 → 跟进 | 教师按校取列表，“查看学情”无动作 | 仅任教范围可读；班级汇总有样本量；个体下钻留痕；可形成跟进记录 |
| J05 看诊断 → 打开原件 → 追问 | 原始依据是假入口，页面/工具权益规则不一致 | 统一权益；只显示许可且正式的报告；原件、引用和问答使用同一版本 |
| J06 学生求助 → 老师回复 → 学生确认 | 新系统只有工单状态；旧系统有双向消息 | 学生可看到接单人/处理进度与回复；老师能看授权上下文、回复、关闭或重开 |
| J07 知识文档 → 审核 → 回答引用 → 下线 | 发布没有接检索；驳回后缺返工入口 | 发布且许可内容才可检索；引用到具体片段；驳回可改；下线不再用于新回答 |
| J08 配置模型/Prompt → 评测 → 发布 → 审计 | 新系统主要是接口/配置底座，缺管理闭环 | 有作用域和审批，回归集通过后灰度；回答能定位版本/工具/证据；异常可回滚 |

## 7. 上线前与首批迭代应先处理的问题

| 优先项 | 证据及影响 | 处理原则 |
|---|---|---|
| 教师超出任教范围 | `_scoped` 仅按学校；教师可用同校管理查询（N07） | 补教师—班级—学科关系和统一策略；聚合与明细分别授权 |
| 全局 Prompt 发布范围 | 学校/QA 管理依赖作用于无租户字段的 Prompt（N09） | 首先限制全局发布；校级覆盖须显式建模，不靠前端菜单 |
| 诊断权益不一致 | 页面直接读 structured_json，工具要求 DIAGNOSIS（N02/N07） | 由产品确认授权政策，所有路径复用同一规则；不能静默放宽 |
| 跨域关联与状态合法性 | 工单 session_id、风险 student_id 需要归属验证；状态字符串直接赋值（N12） | 服务校验 + 数据约束；增加合法状态迁移和审计 |
| 登录演示信息与令牌撤销 | 登录源码始终显示演示账号；撤销状态在进程内（N16） | 生产构建不显示演示凭据，测试账号不获生产权限；多进程前共享撤销存储 |
| 四个虚入口 | 原始依据、加入复盘、查看学情、学校运营详情没有真实动作（N02/N03） | 能补的接通；依赖未到位的明确禁用并解释，不伪装可用 |
| 两条治理断链 | 风险确认后解决按钮消失；知识驳回后无返工入口（N03） | 先补状态闭环，再增加高级 SLA 和批量处理 |
| 来源丢失与流式误称 | 历史无 sources 恢复，只有一次整体 content_delta（N08） | 引用持久化；分清 SSE 协议、实时工具状态与安全输出策略 |

这些是静态代码可定位的缺口，不是本轮已复现的生产事故。P0 在本路线图中表示发布/扩大权限前必须关闭的门禁，不能据此推断已有真实数据泄露。

## 8. 迁移策略与范围取舍

### 8.1 保留、升级、暂缓

- **保留：** 旧业务名词、筛选/列表/详情习惯、原件—区域—草稿—正式题层级、引用保护、人工消息；新身份/工具/会话/导入/追踪内核。
- **升级：** 教务数据真实性、任教范围、来源版本、异步任务恢复、审核状态机、统一设计组件、移动学生体验、配置评测门禁。
- **不照搬：** mock 数据、零实现按钮、固定身份显示、旧“题库/新题库”长期双轨、巨型单页和路由鉴权漏洞、裸 Token 文件链接方式。
- **延后：** 外部采集、大规模智能推送、生成式自动批阅、复杂多 Agent。它们不应阻塞核心旧业务的只读接入和人工生产流程恢复。

### 8.2 推荐分域接入，不做无条件双写

1. 核实旧运行版本、接口契约、表结构、原件存储和可用性；当前归档不能直接当作可运行生产系统。
2. 每个业务域明确一个写入主系统。初期旧题库/试卷仍是来源，新系统只读接入或接收受控快照；新会话/风险/反馈由新系统管理。
3. 以学校、实体类型、来源系统和旧 ID 建稳定映射，使用水位/批次、内容哈希与对账记录；禁止直接把旧整数 ID 当新 UUID。
4. 扩展现有 CSV 事务导入，并补诊断、权益、题目/知识点与附件同步；`sync_service.py` 只 staging 的路径不能误作正式迁移完成。
5. 需要在线共存时增加有审计的 Adapter/同步任务。新界面不直接连旧数据库，也不把新凭据拼到旧页面 URL。
6. 一个域通过回归、数据对账与恢复演练后再切换写主；保留回退窗口。跨库双写只有在冲突、补偿和失败恢复方案明确后才考虑。

这比现有迁移 PRD 的“阶段二双写”更保守，是本分析的建议变更，需技术负责人批准；并未修改既有 PRD。当前仓库有 CSV 导入，不能据文档中的示例 `LegacyMySQLAdapter` 宣称在线旧库 Adapter 已交付（R03、N10）。

### 8.3 需求基线需要统一的三项决策

| 冲突/未决项 | 本路线图默认建议 |
|---|---|
| 学科智能体规范允许一期不依赖 RAG；市级 PRD 把有限课程知识问答纳入试点 | 先交付真实成绩/题目/报告；RAG 列明确独立里程碑。未完成时不开放“审核课程知识问答”承诺 |
| BASIC/DIAGNOSIS 权益与市级公共服务定位如何兼容 | 先保持明确授权边界；是否收费、哪些内容普惠，由业务/法务批准，开发不可自行解释 |
| 旧业务需替代到什么深度 | 区分“可读接入”“业务可操作”“可替代旧系统”三档；只有最后一档通过后才停旧域 |

## 10. 如何使用这份结论

先用路线图的 G0 冻结角色、诊断权益和旧域写主，再执行第一轮 P0 和数据接入。每完成一个任务，回填“界面入口、接口、数据来源、权限、状态流、自动化证据、业务验收人”七项；没有完整证据的功能维持“局部/待核”，不以页面数量上调完成度。
