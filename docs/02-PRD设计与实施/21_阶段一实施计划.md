## 1. 阶段目标

阶段 0—1 只解决可重复开发底座和安全边界，不新增诊断、RAG、教师端或家长端功能：

1. 冻结唯一 API、错误、SSE 和 Tool 契约。
2. 统一 ORM Base、模型导入、Alembic 迁移和 Compose 服务命名。
3. 建立可替换的学校登录适配器、本地开发登录和市—区—学校—班级—学生数据范围。
4. 清除默认密钥、镜像内 `.env` 和匿名管理接口等上线阻断项。

## 3. 工作包

### 3.1 契约冻结（阶段 0）

- 正式 API 仅使用 `/api/v1/auth/*` 和 `/api/v1/chat/sessions/*`；旧 `/api/v1/chat/stream`、`/api/v1/sessions` 标记历史接口。
- 所有错误返回 `{error: {code, message, request_id, details}}`；内部异常只写服务端日志。
- SSE 事件固定为 `message_start`、`content_delta`、`source`、`tool_call_start`、`tool_call_end`、`message_end`、`error`、`done`，每个事件带 `request_id` 和单调递增 `seq`。
- 第一阶段只冻结 `get_exam_summary`、`get_subject_scores`、`get_rank_change`、`get_score_trend`、`get_question_losses`。

### 3.2 数据库与迁移（阶段 1）

- 运行时和迁移统一使用 `app.db.base.Base`；导入所有业务、Prompt、审计模型。
- 对齐模型、迁移和关系字段，禁止 `.backup` 模型参与运行。
- 显式初始化 PostgreSQL 所需扩展；验证 `alembic upgrade head` 在空库和已存在数据环境均可执行。
- 对成绩相关表增加 `school_id`、`student_id`、`exam_id` 一致性约束和带学校前缀索引。

### 3.3 认证与租户边界（阶段 1）

- 定义 `SchoolAuthProvider` 协议；生产接学校 OAuth/API，本地仅使用开发 Provider。
- refresh 必须验证 Token 类型、轮换和撤销；logout 将 refresh token 失效。
- 从 `user_roles` 加载角色，不得把所有账号固定成 `STUDENT`。
- Prompt、Trace、数据导入和管理接口必须认证、RBAC 并校验市/区/学校范围。
- 生产配置拒绝默认或过短密钥；访问令牌不写入镜像和仓库。

### 3.4 Compose 与运维（阶段 1）

- 统一服务名为 `db`、`redis`、`api`、`web`；数据库 URL 不得使用不存在的 `postgres` 主机。
- 开发环境可热重载，试点环境必须使用生产构建、非开发命令和反向代理。
- 增加 `.dockerignore`，禁止 `.env`、虚拟环境、测试数据和 `旧产物/` 进入构建上下文。
- 健康检查必须区分 liveness/readiness；数据库、Redis 不可用时 readiness 返回失败。

## 4. 阶段验收门槛

- [ ] 全新数据库迁移成功，迁移后模型元数据与数据库表一致。
- [ ] 两所学校的学生、会话、成绩、Trace 互相不可见。
- [ ] access token 发送到 refresh 返回 `INVALID_TOKEN_TYPE`。
- [ ] logout 后 refresh 不能再次换取 access token。
- [ ] 匿名访问 Prompt/Trace/导入管理接口返回 401。
- [ ] 镜像不包含 `.env`、默认密钥和 `旧产物/`。
- [ ] 契约测试、静态检查和构建命令均有可复制的通过输出。

未满足任一门槛，阶段状态保持 `in_progress`，不得在文档中写“完成”或“生产就绪”。
