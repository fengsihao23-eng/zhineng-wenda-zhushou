> 本文不描述当前完成度。只有阶段 5 试点放行后，后续版本才可排期；任何能力不得因写入路线图而提前开放。

## 1. 演进前置条件

后续功能必须满足：市级身份和学校隔离稳定、成绩数据有同步批次、AgentRun/Tool/Audit 可追溯、监控和人工处置流程可用。未满足时只修复稳定性和安全问题。

## 2. 版本顺序

| 版本 | 能力 | 前置条件 | 放行重点 |
|---|---|---|---|
| V1 试点 | 成绩、考试、错题事实问答 | 阶段 0—5 全部门槛 | 数据正确、隔离、安全、可追溯 |
| V2 | 诊断报告解释 | 合法权益、报告结构化、人工审核 | 只解释报告已有内容，不推断未授权结论 |
| V3 | 教材与校本知识库 | 内容授权、版本和下架机制 | 来源、版本、引用准确 |
| V4 | 错题与相似题 | 题目版权、题目质量和答案校验 | 不泄露其他学生题目或答案 |
| V5 | 知识点掌握模型 | 长期数据授权和评估集 | 可解释、可撤回、可人工纠正 |
| V6 | 学习计划与练习 | 未成年人保护和教师运营流程 | 时间、难度和负担可控 |
| V7 | 长期学生记忆 | 明示同意、导出删除和保留期限 | 学生可查看、修改和清除 |
| V8 | 多学科/多 Agent | 单 Agent 稳定性与成本证明 | 明确边界、预算和故障降级 |

## 3. 明确后置范围

在 V1 试点放行前不实施：诊断报告问答、RAG、学习计划、教师端、家长端、图片题、语音、多 Agent 和全市正式推广。

## 4. 版本准入模板

每个后续版本必须提交：产品目标、数据授权、API/数据迁移、模型风险、隐私评估、灰度方案、回滚方案、离线评估集、线上监控和签字验收。没有这些材料，状态只能是 `proposed`。
