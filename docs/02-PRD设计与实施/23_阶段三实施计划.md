> 第一版试点只做成绩、考试和错题事实问答。诊断报告、RAG、教师端、家长端和多 Agent 不在本阶段范围内。

## 1. 阶段 3：成绩问答垂直闭环（2—3 周）

先实现非流式 HTTP，使用 `FakeModelProvider` 验证主链路，再接入真实模型：

```text
登录
  → 创建会话
  → 保存用户消息
  → 构建学生上下文
  → 意图识别
  → 调用只读 Tool
  → FakeModelProvider 生成答案
  → ResponseGuard
  → 保存 assistant 消息
  → 保存 AgentRun/Tool/ModelUsage/Audit
  → 返回答案、来源和 agent_run_id
```

### 1.1 强制约束

- 只保留一套 `AgentLoop`；每个 Tool 使用 `execute(tool_context, args)`。
- `school_id`、`student_id`、`user_id` 从认证上下文注入，模型参数不能覆盖。
- 成绩、排名、差值等数字必须来自 Tool；模型只能组织语言。
- Tool 错误、模型超时、Guard 拦截和空数据都返回稳定错误码并落审计。
- 主链路必须能查询 `agent_run_id` 对应的 Prompt、Tool、模型用量、Guard 和最终消息。

### 1.2 阶段 3 验收

- [ ] 学生可创建会话、发送消息、读取历史消息。
- [ ] 五个正式 Tool 均有成功、空数据、越权和异常测试。
- [ ] FakeModelProvider 覆盖普通文本、Tool call、超时和错误。
- [ ] 两所学校的数据、会话和 Trace 互相不可读。
- [ ] 每个答案都能追溯到数据批次和 AgentRun。

## 2. 阶段 4：SSE 与前端（1—2 周）

前端普通 JSON 和 SSE 请求均使用同一 API 客户端、Token 刷新和错误处理策略。SSE 使用 `fetch` POST，不使用原生 `EventSource`。

必须实现：

- 服务端创建会话、会话列表和历史消息；
- `message_start`、`content_delta`、`source`、`tool_call_start`、`tool_call_end`、`message_end`、`error`、`done` 事件；
- 按 `seq` 去重，断线带最后序号恢复；
- 停止生成、重试、过期登录处理、来源展示和反馈；
- Nginx 的 HTTP/1.1、`proxy_buffering off`、长 `proxy_read_timeout` 和 SSE 长连接。

### 2.1 阶段 4 验收

```text
登录 → 新建会话 → 发送问题 → 收到 content_delta
→ 收到 source → 收到 message_end → 刷新后历史仍存在
```

以上流程必须在真实浏览器 E2E 中通过；网络中断、Token 过期和后端错误必须有可见且可恢复的状态。

## 3. 阶段 5：试点准备（2 周）

必须完成：

- PostgreSQL 集成测试和 Playwright 主流程；
- 跨学校越权、Token、限流、提示注入和敏感信息测试；
- CSV 导入失败/重试、备份恢复和模型供应商故障测试；
- 500、2000、5000 并发阶梯压测及容量结论；
- 学校管理员审计页面和内容安全人工升级流程；
- 私有服务器 Docker Compose 部署、回滚和运维手册。

## 4. 试点放行门槛

3—5 所学校试点前必须全部满足：

- P0 缺陷为 0，跨学校越权为 0；
- 核心 E2E、SSE 断线恢复和安全测试通过；
- 成绩回答 100% 有 Tool、数据批次和 AgentRun 证据；
- 默认密钥、`.env` 和 `旧产物/` 不进入镜像；
- 备份可恢复，告警、日志和审计可查询；
- 运营人员可停用 Prompt、Tool 和数据批次。

任一证据缺失都只能标记为 `pilot_blocked`，不得写“生产级”或“全市可用”。
