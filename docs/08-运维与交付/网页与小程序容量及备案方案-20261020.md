# 网页与小程序容量及备案方案

日期：2026-10-20。状态：选型建议，待实际报价、资源开通、部署优化及容量验收。

预算偏好已由用户确认：**先按稳定性出方案，再核对实际报价**。配置、计费拆分、供应商询价文本及账号价待核项目见 [正式环境询价与费用核对单](正式环境询价与费用核对单-20261020.md)。

## 1. 用户确认的规模

- 网页、小程序和网页管理员共用学校账号、后端、业务数据库、权限及每日提问额度。
- 总用户按 **1–3 万人**，高峰按 **1000 名不同账号同时在线**规划。
- 1000 人在线不等于 1000 人同时请求模型；同一账号多个设备的请求仍会共同消耗后端资源。
- 每账号每日 100 次是配额上限，不是预计每日提问量；云资源费用和模型按量费用分别核算。

## 2. 现状核查

本次通过服务器只读检查确认：现有部署在腾讯云中国香港地域，2 vCPU、约 4GB 标称内存、约 60GB 系统盘，API 配置为 1 个工作进程。Web、API、PostgreSQL、Redis、Nginx 位于同一台服务器。

现有业务链路及真实模型已完成小规模联调；尚未完成千人在线容量验证。香港实例不能作为腾讯云大陆 ICP 备案的云资源。腾讯云当前要求备案 CVM 位于中国内地、包年包月购买至少 3 个月、备案期间剩余有效期至少 1 个月，并具备非零带宽及符合要求的公网 IP；该文档明确不支持仅绑定 EIP 用于此项备案。[腾讯云备案云资源要求](https://cloud.tencent.com/document/product/243/18908)

## 3. 正式环境建议起配

以下规格是用于报价、部署和压测的工程起点，不是已经验证可承载 1000 人的套餐承诺。优先评估腾讯云广州，同一地域、同一 VPC，应用与数据库分开部署。

| 资源 | 建议起配 | 用途与边界 |
| --- | --- | --- |
| 应用服务器 CVM | 标准型 x86，**4 核 8GB × 2 台**，分布在两个可用区；每台 100GB SSD 系统盘 | API、鉴权、问答编排及网页服务；支持后续增配和加节点 |
| 负载均衡 CLB | 1 个公网 HTTPS 入口，健康检查、连接数和新建连接数容量按压测核定 | 两台应用分发请求；单节点异常后将新请求分发至健康节点 |
| PostgreSQL | **4 核 16GB，高可用版，200GB SSD 起**；版本与当前 PG15 兼容，需支持项目所用 pgvector 扩展 | 学校账号、考试、成绩、授权、会话、留言和配额；自动备份与可恢复能力必须验证 |
| Redis | **2GB 主从／高可用规格起** | 跨实例限流、缓存及后续任务调度；账务与配额事实仍以业务数据库为准 |
| 私有对象存储 COS | 按报告实际体积开通，先核对 100–500GB 的报价档位 | 原始 PDF、备份及可复用的报告处理产物；保留服务端权限和版本检查 |
| 静态资源分发 | 网页 JS、CSS、图标等公共静态资源使用 CDN | 用户成绩、聊天、授权接口及私有报告不进入公共缓存 |
| 公网带宽 | 应用节点需满足模型出网与备案条件；入口按 **20–50Mbps 峰值**先询价，并保留增配能力 | 这是初算范围；集中登录、文件下载峰值及 CDN 回源量须实测后确定，分别核算 CLB、CVM 与 COS 出网 |

两台应用服务器需要完成状态共享、连接池配置及文件访问适配后再投入服务。CLB 可以跨可用区分发流量、隔离不健康节点；这不等于在途请求自动成功，客户端仍需使用既有幂等重试。[腾讯云负载均衡说明](https://cloud.tencent.com/document/product/214/524)

当前模型通过外部 DeepSeek API 调用，首期应用服务器不需要 GPU。数据库规格、存储大小和公网峰值在获取实际成绩量、PDF 总量及购买页报价后调整，不预先锁定长期大额订单。

## 4. 先推进备案的购买顺序

1. 确认公司实名的腾讯云账号及准备备案的公司域名，核对主体资料。
2. 先从上述方案开通 **1 台广州标准型 CVM：4 核 8GB、100GB 系统盘、Ubuntu 24.04 LTS、包年包月至少 3 个月**。购买页确认公网 IP 类型、非零带宽及备案资格；不要只购买按量或仅绑定 EIP 的实例后假定能备案。
3. 使用符合条件的资源及域名提交备案。备案流程中的接入信息按平台要求填写，不需要先迁移全部现有数据才开始准备材料。新备案通过前不将正式业务切到未备案大陆域名。
4. 备案处理期间完成第二台应用、数据库、Redis、存储、HTTPS 及容量优化的准备与询价。
5. 备案通过、容量验收及迁移核对完成后，再按计划切换正式入口；可按一个 HTTPS 域名承载网页和 `/api/v1`，小程序请求同一套 API。

网站备案和小程序备案均需处理；已有网站备案的主体可以补充 APP／小程序相关信息，不能把网站备案号直接视为小程序手续已完成。[工信部通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)

## 5. 千人规划的负载假设

先用以下可调整场景组织验收：

- 1000 名不同账号持续在线，至少持续 30 分钟，包含网页及原生小程序的客户端行为。
- 若每人每分钟问 1 次，平均为 `1000 / 60 ≈ 16.7` 次问答请求／秒，先以 **20 次／秒**作问答场景。
- 若模型响应耗时为 3–25 秒，对应约 `20 × (3–25) = 60–500` 个在途模型请求。这是负载推算，不是生产吞吐测量。
- 两端现有实现每 30 秒续期并读取状态。1000 个活动客户端大约产生 33 次续期及 33 次状态读取／秒，还需叠加登录、提问、报告访问及多设备流量。
- 分开测集中登录、历史较多的账号、成绩查询、报告 PNG 预览、原 PDF 下载、管理员办理留言和后台导入，避免仅用空会话／空报告证明容量。

DeepSeek 官方当前对 Flash 公布账号级 2500 个并发连接限制，同账号多个 API Key 合并计数；仍需确认实际业务账号的可用配额和其他系统占用，并验证排队时延及费用。接口配额不能替代本系统的吞吐测试。[DeepSeek 并发说明](https://api-docs.deepseek.com/quick_start/rate_limit/)

## 6. 规模上线前的技术工作

现有功能通过不表示这些规模工作已经完成：

1. **缩短问答数据库事务**：目前一条问答的事务跨越外部模型调用，等待期间占用连接与该账号额度行锁。需保持原子配额、幂等和故障退款语义，再拆分长事务；不能仅把数据库连接数放大。
2. **配置多进程连接预算**：数据库连接池当前每进程 `10 + 20` 溢出连接，多进程、多实例合计需要统一预算，并核对数据库连接上限及超时。
3. **降低全量同步成本**：当前状态接口会读取最多 100 个会话并重新核验历史来源。需在保留权限检查的前提下分页、按需加载和合并重复读取；在线人数统计也需按实测优化。
4. **限制模型在途请求**：增加跨节点并发控制、受限等待、明确繁忙反馈及超时策略。现有在线人数拥堵提示只展示等级，没有实现自动排队或扩容。
5. **隔离报告处理**：PDF 渲染与文本提取目前发生在请求链路；将耗时处理移出请求事件循环，并复用当前版本的处理产物。现有 PDF 原文存储在 PostgreSQL，转 COS 需实施迁移及逐次鉴权，尚非当前已完成功能。
6. **维持两端语义**：共享账号、权限、配额、会话和留言；跨节点验证撤权、令牌撤销、同请求重试及最后一次额度争抢。
7. **监控和恢复**：观测 API 延迟／错误率、数据库连接与锁等待、模型在途与耗时、PDF 处理时间、带宽及费用；完成数据库恢复演练与切换回滚验证。

## 7. 容量验收与迁移

先在隔离业务库使用带真实延迟特征的测试模型验证本系统，再以受控真实模型调用核对实际端到端表现与费用。未经协调不直接向现有业务站点发起千人压力。

验收至少记录：吞吐、P50/P95/P99、业务成功率与 5xx、模型等待和处理时间、连接／内存／CPU／磁盘／带宽峰值，注明数据规模、文件大小和账号历史量。性能目标需在采购报价及压测场景确定后形成门槛，不以“1000 人能打开页面”替代问答及报告链路容量。

迁移顺序为备份 → 新环境恢复与校验 → 隔离验收 → 切换期间控制写入并同步最终数据 → 校验账号、授权、成绩、文件、会话和额度 → 切换域名 → 验证 → 保留可回滚快照。最终开放前关闭小程序域名调试豁免并完成真机验证。

## 8. 给备案同事的交接摘要

> 我们按网页端和微信小程序共用后台来规划，预计 1–3 万总用户、高峰 1000 人同时在线。服务器建议用腾讯云广州标准型 CVM，正式配置先按两台 4 核 8G 应用服务器、独立高可用 PostgreSQL 和 Redis、负载均衡及私有文件存储询价。为了先推进备案，可以先开通其中一台广州 4 核 8G、100G 系统盘的包年包月实例，购买至少三个月，并在购买页确认公网 IP、非零带宽和备案资格。现有香港服务器用于过渡，后续业务迁移到大陆正式环境。网站域名备案和微信小程序备案分别推进。

待补充信息：公司域名、云账号实名认证主体与账号级报价、初期学校／考试数、成绩量与报告体积。预算按稳定性优先核价；实际价格以购买页资源规格、带宽计费和续费报价为准，模型调用预算另列。
