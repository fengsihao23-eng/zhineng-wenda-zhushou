# 腾讯云部署指南

目标：把系统放到一台 **24 小时运行**的云服务器上，经理随时可以打开，不再依赖本机的临时隧道。

本指南只解决部署与运维；**是否把真实师生数据上传到云服务器，属于学校的数据授权决定**，见文末「数据放置决策」。

## 1. 购买前的准备

| 项目 | 建议 | 说明 |
| --- | --- | --- |
| 机型 | 轻量应用服务器或 CVM，**2 核 4G** 起 | Compose 同时运行 Postgres、Redis、API、Web、Nginx；1G 内存容易因构建而失败 |
| 系统盘 | 60 GB 起 | 系统、镜像、数据库和备份 |
| 系统 | Ubuntu 22.04 / 24.04 LTS | 与仓库的 Docker 部署脚本一致 |
| 地域 | 学校在阳江，选**广州** | 延迟最低 |
| 带宽 | 按固定带宽 3–5 Mbps 起 | 纯文本页面足够；上传 Excel 时才需要带宽 |

**备案要求**（务必先看清，否则网站无法通过域名访问）：

- 服务器在中国大陆：**域名必须完成 ICP 备案**才能绑定访问，备案通常需要 1–3 周，并需要学校主体材料。
- 不想备案：只能选香港/海外地域，但延迟更高；真实师生数据出境需要额外评估，通常不适合当前场景。

## 2. 安全组（只开三个端口）

在腾讯云控制台的安全组入站规则中仅保留：

| 端口 | 来源 | 用途 |
| --- | --- | --- |
| 22 | 只填你自己的公网 IP | 远程运维 |
| 80 | 0.0.0.0/0 | HTTP（用于证书签发与跳转 HTTPS） |
| 443 | 0.0.0.0/0 | HTTPS 入口 |

数据库 5432、Redis 6379、API 8000 **不要对公网开放**：Compose 里它们只在内部网络暴露。

## 3. 服务器初始化

用腾讯云的「网页登录」或 SSH 登录服务器。仓库里提供了初始化脚本，也可以手动安装。

```bash
# 方式一：使用仓库脚本（安装 Docker、Compose 插件并设置时区）
scp -r scripts/server root@<服务器IP>:/root/
ssh root@<服务器IP> 'bash /root/server/bootstrap_ubuntu.sh'

# 方式二：手动安装
sudo apt-get update && sudo apt-get install -y docker.io docker-compose-plugin git
sudo systemctl enable --now docker
```

## 4. 首次部署

```bash
sudo mkdir -p /srv && cd /srv
sudo git clone https://github.com/fengsihao23-eng/zhineng-wenda-zhushou.git app
cd app

# 生成强随机密钥，避免使用模板占位值
cp .env.example .env
python3 - <<'PY'
import secrets, pathlib
path = pathlib.Path('.env')
text = path.read_text()
replacements = {
    'POSTGRES_PASSWORD=your_secure_password_here': f'POSTGRES_PASSWORD={secrets.token_urlsafe(24)}',
    'SECRET_KEY=your_secret_key_here': f'SECRET_KEY={secrets.token_urlsafe(48)}',
    'JWT_SECRET_KEY=your_jwt_secret_key_here_minimum_32_characters': f'JWT_SECRET_KEY={secrets.token_urlsafe(48)}',
}
for old, new in replacements.items():
    assert old in text, old
    text = text.replace(old, new)
path.write_text(text)
PY
chmod 600 .env
docker compose config >/dev/null   # 校验变量，不会启动服务
docker compose up -d --build
docker compose ps
curl -sS http://127.0.0.1/api/v1/health
```

数据库迁移在 API 容器启动时自动执行，无需手工操作。

## 5. 创建第一个正式账号

`APP_ENV=production` 会拦截示例账号（`*_demo`、`demo_school`、默认密码 `password123`），所以**必须**用下面这个脚本创建登录账号：

```bash
docker compose exec api python scripts/create_school_account.py \
  --school-code 441701001001 --school-name 阳江一中 \
  --username admin01 --role SCHOOL_ADMIN

# 经理只读账号（推荐：只有查看权限）
docker compose exec api python scripts/create_school_account.py \
  --school-code 441701001001 --username manager_view \
  --role SCHOOL_VIEWER --display-name 经理查看
```

- 密码由脚本随机生成并**只打印一次**，请当场通过安全渠道转交；脚本不会保存密码。
- `--force-change-password` 可要求该账号首次登录后修改密码。
- 忘记密码时用 `--reset-password` 重置，不会影响其他数据。

## 6. 域名与 HTTPS

1. 在腾讯云 DNS 解析里把域名（例如 `zhineng.example.edu.cn`）指向服务器公网 IP。
2. 申请证书（腾讯云免费 SSL 证书即可），把文件放到仓库目录：

```bash
mkdir -p infra/nginx/certs
cp fullchain.pem infra/nginx/certs/fullchain.pem
cp privkey.pem  infra/nginx/certs/privkey.pem
chmod 600 infra/nginx/certs/*.pem
sed -i 's/^TLS_ENABLED=.*/TLS_ENABLED=true/' .env
docker compose up -d nginx
```

证书缺失时 Nginx 会拒绝启动，这是刻意设计，避免误以为已加密。**不要长期只用 HTTP**：登录凭据和师生数据都需要加密传输。

## 7. 数据放置决策

| 方案 | 适用场景 | 代价 |
| --- | --- | --- |
| **A. 只放合成演示数据**（默认） | 先验证部署、给经理看界面与流程 | 经理看到的不是真实档案 |
| **B. 迁移真实师生数据** | 经理需要随时查真实档案 | 需学校书面同意数据存放在云服务器；迁移与备份都要受控 |

方案 B 必须先取得学校批准，再按下面的步骤执行，全程不要经过 Git 或聊天工具：

```bash
# 1) 在本机（数据源）导出，先确认不含其它无关库
docker compose exec -T db pg_dump -U postgres -d intelligent_qa -Fc > /secure-path/roster.dump
# 2) 用 scp/sftp 上传到服务器，仅临时存放
scp /secure-path/roster.dump root@<服务器IP>:/srv/roster.dump
# 3) 服务器上恢复到目标库（会覆盖现有数据，脚本会要求确认）
docker compose exec -T db pg_restore -U postgres -d intelligent_qa --clean --if-exists < /srv/roster.dump
# 4) 立即删除中转文件，并再次确认账号与权限
rm -f /srv/roster.dump /secure-path/roster.dump
```

迁移完成后要复核：学生/教师档案数、随机抽查若干条、以及各角色能看到的数据范围。

## 8. 备份与定时任务

```bash
# 手动备份（默认保留最近 7 天）
BACKUP_DIR=/srv/backups ./infra/scripts/backup-db.sh

# 每天 02:30 自动备份
sudo crontab -e
30 2 * * * cd /srv/app && BACKUP_DIR=/srv/backups ./infra/scripts/backup-db.sh >> /var/log/zhineng-backup.log 2>&1
```

备份文件含真实师生信息，请限制权限（`chmod 700 /srv/backups`），并定期**演练恢复**：

```bash
./infra/scripts/restore-db.sh /srv/backups/intelligent_qa_YYYYmmdd_HHMMSS.sql.gz
```

## 9. 日常更新与排障

```bash
cd /srv/app
git pull                                   # 拉取新版本
docker compose up -d --build               # 重建并滚动重启
docker compose ps                          # 健康状态
docker compose logs -f api                 # 应用日志
docker image prune -f                      # 清理旧镜像
```

模型问答需要 `DEEPSEEK_API_KEY`（或其它 provider 配置）写入 `.env`，否则页面可用但智能问答不可用。健康检查里 `model.real_model_ready=false` 即表示模型未就绪。

## 10. 上线前检查清单

- [ ] 安全组只开 22/80/443，22 限定来源 IP
- [ ] `.env` 中 `POSTGRES_PASSWORD`、`SECRET_KEY`、`JWT_SECRET_KEY` 均已替换为随机值，文件权限 600
- [ ] `APP_ENV=production` 且未开启示例账号
- [ ] 已用 `create_school_account.py` 创建正式账号，示例账号登录被拒绝
- [ ] 域名已解析、备案已完成、`TLS_ENABLED=true` 且 HTTPS 可访问
- [ ] 每日自动备份已配置，并演练过一次恢复
- [ ] 经理使用只读账号（SCHOOL_VIEWER），仅在需要时分配管理权限
- [ ] 若迁移了真实数据，已取得学校书面同意并复核数据范围
