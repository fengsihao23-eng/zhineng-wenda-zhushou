# 报告批量上传与小程序对话恢复

报告管理原先每批只允许 30 份、合计 30 MB；小程序每次冷启动没有选中原会话，已保存的记录只能从学习工具进入。

## 交付行为

- 每次可选最多 500 份 PDF，合计最多 1 GiB；单份仍为 15 MiB、100 页，同批仅一个科目。
- 网页自动按至多 20 份、20 MiB 分段传输并显示进度，最终清单只携带文件引用，一次确认保存。无需管理员手动拆分上传批次，也无需提高网关全局请求体上限。
- 每份文件在传输时校验 PDF 与可渲染性；最终仍核验考试修订、命名、归属、预览确认与重复报告。任一失败整批不写入，保存结果丢失后以原请求标识重试不会重复创建。
- 新增 `staged_report_pdfs` 临时表，文件只属于上传管理员与学校，24 小时后失效；移除、切换考试、取消或保存时清理，后续传输顺带清理过期文件。同一管理员待保存文件最多 2 GiB。临时文件未建立查询授权。
- 保存时在数据库内部复制 PDF 到正式版本表，避免 API 一次载入数百份二进制文件。
- 小程序问答顶部增加「历史对话」「新对话」。重开恢复该账号上次会话，无本机记录时打开最近更新的一条；主动新对话保留为空白，后台刷新不会覆盖。只在本机保存会话 ID，答复仍从后台按当前权限读取。
- 历史按最后更新时间查询最近 100 条，旧会话继续后可进入最近列表。退出登录清除本机指针，后台历史保留。

## 验证与部署

数据库增加迁移 `029_staged_report_pdfs`，前置为 `028_school_operator_audit`。上线需先备份，再更新 API 与网页；小程序代码需重新生成扫码预览包，服务器源码更新不会替换手机已有包。

本机证据位于被 Git 忽略的 `.local/report-500-history-20261106/`。验证包括：

- SQLite 与 PostgreSQL 的报告管理、500 份实际 PDF 原子保存、上传私有性及过期检查、问答历史等 32 项；批量总量超过旧 30 MiB 上限，500 份成功，第 501 份拒绝，故障不写入、重复保存只产生一次操作。
- 浏览器上传抽屉、真实 PDF 预览及保存、独立滚动两项通过；另实测一次选择 500 份并分成 25 次传输，进入归属核对步骤，501 份在上传前拦截。
- 原生 Page 模块与隔离真实 API 的 16 个场景，包括重启恢复上次会话、历史跳转、新对话保持空白、账号隔离和撤权隐藏。

正式环境回退保留新增表与迁移；回退镜像需包含迁移文件，使旧业务代码能够在新数据库版本上启动，避免删除临时文件或回退既有业务数据。
