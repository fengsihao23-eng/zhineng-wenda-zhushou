# 超级管理员学校筛选

## 页面与操作

超级管理员首次进入业务工作台时，先选择一所学校，再查看该校数据。支持按学校名称、学校编码搜索，两项查询可组合；名称和编码选择框联动，当前学校在筛选栏持续显示。切换模块时沿用当前学校；切换学校时取消旧请求，清空查询缓存、列表勾选及打开的编辑 / 明细状态。退出登录后清除选择。

覆盖教师档案、学生档案、考务管理、报告管理、提示词及人工，以及运营总览、学校运营、知识库、反馈、风险、人工转接。列表增加学校名称，主要列表同时显示编码，卡片和操作历史显示学校归属。

管理员与操作历史页补充名称 / 编码联动筛选，保留「全部学校」以便处理尚未分配学校的待授权账号。未绑定学校的一次性注册密钥不伪造学校归属。

普通学校管理员保持原来的本校范围，不提供跨学校切换。

## 后端范围

- 所选学校通过 `X-School-ID` 传给业务 API；只允许数据库中具有 `SUPER_ADMIN` 角色的账号使用。
- 仅在学校管理类接口内切换工作范围，不修改登录账号的真实 `school_id`、角色或 Token 身份。
- 名称和编码均来自同一个学校记录，筛选最终使用学校 UUID；无效 / 不存在的学校明确拒绝，不回退到其他学校。
- 已选择学校的查询、详情、创建、修改和审计均使用该校范围；选 A 校不能访问 B 校资源。停用学校只可读取。
- 未传该头的旧客户端保持现有接口权限语义，新的超管页面会阻止在未选学校时加载业务数据。
- 为支持超管维护其他学校的提示词，修订 `028_school_operator_audit` 将 `answer_operations` 的操作人关联改为直接引用账号 ID；目标学校仍单独保存。业务数据的学生、成绩、会话、报告等学校联合约束保持不变。
- 历史修订 024 使用实时模型建表，因此 028 兼容新库已经具有新外键、旧库仍具有旧外键两种状态。回退时遇到已有跨校操作历史会停止，避免破坏审计关系。
