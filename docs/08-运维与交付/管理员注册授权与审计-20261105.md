# 管理员注册、授权与审计

## 使用流程

1. 现有 `admin` 登录后进入「管理员与操作历史」（`/ops/administrators`）。
2. 超级管理员生成一次性注册密钥，可填写用途备注，有效期 1–30 天，默认 7 天。密钥只显示一次，数据库保存 SHA-256 摘要，可撤销。
3. 新管理员从登录页进入「学校管理员注册」（`/register-administrator`），输入密钥和姓名。账号可手填 8 位数字，也可留空随机生成，支持前导零；联系电话可选，不作为登录账号。密码非空即可，无复杂度要求，接口仅保留 4096 字符的请求长度上限。
4. 注册后保存为 `pending`，没有学校和任何角色，不能登录或访问业务数据。成功页面显示最终账号。
5. 超级管理员在账号列表筛选「待授权」，选择学校及权限方案并启用：学校管理 `SCHOOL_ADMIN`、考务管理 `EXAM_ADMIN`、全校只读 `SCHOOL_VIEWER`、质量管理 `QA`。沿用各角色已有的服务端权限，不允许注册人自授权限或获得跨校 / 超级管理员角色。
6. 超级管理员可查看账号资料、修改管理员资料 / 权限、禁用或启用账号。权限、学校、状态、资料更新采用版本检查，避免覆盖并发修改。每次变更使旧登录凭据失效。
7. 忘记密码由超级管理员重置，可选择下次登录强制修改。支持「全部账号」查看学生、教师和管理账号的基本资料及重置密码。原密码、密码哈希和密钥摘要均不通过这些接口返回。

账号归属学校可在授权时指定。已绑定原学校业务历史的账号，如果数据库联合外键禁止改校，会保留原归属并返回明确提示；应禁用旧账号、创建新学校账号，避免迁移旧学校的业务历史。附带教师 / 学生等身份的旧账号仍由对应档案流程管理其学校与业务权限。

## 现有 admin 与迁移

上线前需执行 `alembic upgrade head`，新增修订 `027_admin_invitations`，再启动新版 API 与前端。运行示例：

```bash
docker compose run --rm api alembic upgrade head
docker compose up -d api web
```

部署应使用包含本次代码的镜像。2026-11-05 已按下方上线记录部署到阿里云深圳环境。

2026-11-02 的运维记录显示现有 `admin` 当时仅有 `SCHOOL_ADMIN`。本次迁移按用户要求，为唯一的、启用中的 `general` 类型 `admin` 且已有 `SCHOOL_ADMIN` 的账号增加 `SUPER_ADMIN`，保留原账号、密码及原角色。升级增加凭据版本，要求重新登录，并新增 `administrator.bootstrap` 审计事件。

- 已有 `SUPER_ADMIN` 时不重复授权或重复留痕。
- 新数据库没有 `admin` 时不创建默认账号或默认密码。
- 存在多个启用的 `admin`，或该账号不是预期学校管理员时，迁移整体失败，需先确定旧账号身份。
- API 按数据库角色判断超级管理员，不按用户名赋权。
- 回退结构不会自动撤销已授予的超级管理员权限或删除审计历史。尚有未分配学校的待授权账号时，降级会停止，避免数据丢失。

## 历史记录范围

超级管理员可按学校、账号、操作类别、成功 / 失败、时间范围分页查询：

- 注册、授权、学校 / 权限 / 状态 / 资料变更，保存修改前后快照；
- 密钥创建与撤销；
- 管理员登录（包括已知账号的失败尝试）、退出、密码重置 / 修改；
- 通过认证依赖的管理员请求，记录操作人、请求编号、路由模板、方法、响应码、资源标识和连接来源 IP；
- 既有业务审计记录。

不记录请求正文、密码、Token 或密钥明文。普通管理员不能通过新接口或旧审计入口读取管理员治理事件。连接来源 IP 为服务端实际连接对端，在代理部署中可能是网关地址。身份尚不能确认的请求、限流前拒绝的请求、历史上未产生的日志不构成可恢复的管理员历史。通用请求日志写入失败会记录服务端错误；注册、授权及重置密码的业务审计与业务修改同事务提交。

成功读取审计列表不会再新增一条访问记录，避免翻页操作本身不断改变列表；无权限读取的尝试仍记录。

## 学校隔离现状

现有系统使用共享 PostgreSQL 数据库、共享表，以 `school_id` 做后端查询范围约束，并通过联合外键约束学生、考试、成绩等核心关系的学校一致性。超级管理员和市级运营角色具有设计上的跨校范围。

本次没有添加 PostgreSQL RLS，也没有创建每校独立数据库。不能将联合外键描述为查询层面的数据库行级隔离。待授权管理员允许暂时没有 `school_id`，数据库检查约束保证只有带管理员编码且处于 `pending` 的账号可无学校；激活必须先分配学校。
