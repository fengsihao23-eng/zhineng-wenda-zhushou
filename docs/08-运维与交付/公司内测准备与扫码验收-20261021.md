## 2. 个人主体与正式发布的边界

腾讯官方现有说明明确：深度合成类目仅向非个人主体开放，个人主体无法申请该类目，AI问答正式发布需核对实际适用类目与资质。因此本阶段准备内部开发测试，正式公开发布资格须在小程序后台另行核实；不能承诺个人主体能够正式发布本项目的AI问答功能。[腾讯官方说明](https://docs.cloudbase.net/ai/release/algorithm-filing)

开发版上传、预览、体验成员等能力也以该账号实际后台为准。拿到AppID后先验证这些步骤；若平台限制该功能的开发／体验使用，记录原始提示，再确定企业主体等后续路径。

## 3. 需要本人完成的注册步骤

1. 打开 [微信公众平台](https://mp.weixin.qq.com/)，选择注册小程序。
2. 按页面提示完成邮箱验证，主体选择“个人”，由本人填写信息并用本人微信完成所需验证。
3. 进入小程序后台的开发设置，复制以 `wx` 开头的AppID。菜单名称以当前后台为准。
4. 将AppID提供给工程配置。若页面卡住，提供当前页面截图并遮挡身份证号、验证码等内容。

邮箱、短信、人脸／身份验证及管理员扫码等本人步骤在本机完成；工程配置需要AppID，不需要在聊天中提供密码或AppSecret。当前登录仍使用学校账号，不依赖微信AppSecret。

## 4. 工程配置与预览

在取得有效AppID后，使用现有原生工程，不增加第二套业务库。当前接口地址为 `http://43.161.195.51/api/v1`。内部调试配置命令如下，示例AppID须替换成实际值：

```bash
npm run mini:configure -- --appid wx实际AppID --api http://43.161.195.51/api/v1 --local
npm run mini:check
```

之后在微信开发者工具中编译并尝试生成开发预览码，核对实际返回结果。`--local`仅配置开发调试中的域名校验豁免，不会让HTTP地址自动满足微信正式网络要求。

手机网络分两种情况核验：

- 有已满足微信后台要求的域名：可为原服务器配置HTTPS，并按实际平台要求设置request和downloadFile合法域名。需核对域名备案状态和当前可用性；继续使用旧服务器不要求迁移到新服务器。
- 暂无该域名：仅尝试平台允许的开发预览及手机调试模式。登录／问答的request和报告downloadFile分别实测，不能因开发者工具可请求就承诺手机联网成功。

如果正在办理域名备案，按接入商流程协调解析；不擅自改变办理中的域名用途或接入信息。当前没有可用于关闭调试模式验收的已确认HTTPS域名。

`mini:check -- --release`仅作工程配置检查，不能验证微信主体资格、类目、备案或成员权限。本阶段不以该检查替代平台核验。

## 5. 同事的两层访问权限

1. **微信侧权限**：按实际后台允许的成员角色添加同事，确保其微信能够扫描当前开发／体验码。测试者需用自己获授权的微信，不承诺任意微信扫码即开。
2. **业务侧权限**：由网页管理员准备教师／学生测试账号，开放指定考试、科目及测试报告；微信成员身份本身不会授予考试数据权限。

当前曾用于原生界面实测的学生账号只有2场已授权考试、0份已授权报告；需要测报告的账号必须另有对应授权。测试数据范围由业务管理员指定。

## 6. 手机与双端验收顺序

1. 有效AppID能够编译和生成原生预览码，持有人手机成功打开。
2. 同事自己的微信获得允许的预览／体验权限，实际扫码成功。
3. 手机正常登录学校测试账号，首登改密时流程可完成。
4. 提交一条带“公司内测”标记的成绩问题，取得非兜底真实模型回答，核对来源与后台分数。
5. 网页端能读到同一会话，小程序刷新后也可继续；两端额度每次合计扣1次。
6. 使用已授权测试报告核对PNG预览、翻页与PDF下载，访问被撤销时重新阻断。
7. 提交测试留言，由网页管理员领取、核对、回复，手机刷新后可查看、追加及关闭。
8. 退出／重进、账号切换和权限变化后核对数据隔离。保留必要截图及脱敏结果，正式数据不上传公开仓库。

原生二维码的交付以AppID、平台权限和手机联网实测通过为条件。现有网页仍可独立用于公司内问答测试。
